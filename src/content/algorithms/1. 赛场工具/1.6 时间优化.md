### 时间优化
---
以下优化选项适用于 GCC / GNU C++，默认不启用，卡常时按需选择。普通题目优先使用评测机提供的 `-O2` 优化
#### 编译优化
```cpp
// ===== 方案一：O3，优先尝试 =====
#pragma GCC optimize("O3")
// ===== 方案二：O3 + 循环展开，实测有效时使用 =====
#pragma GCC optimize("O3,unroll-loops")
// ===== 方案三：Ofast，确认语义安全后使用 =====
#pragma GCC optimize("Ofast,unroll-loops")
```
上述三个方案只保留一个，`O3` 不保证比 `O2` 快，循环展开也可能导致代码体积增大
#### CPU 指令集优化
---
```cpp
// ===== AVX2 / POPCNT：确认评测机支持后使用 =====
#pragma GCC target("avx2,popcnt")
// ===== 扩展位运算指令：确认全部支持后使用 =====
#pragma GCC target("avx2,bmi,bmi2,lzcnt,popcnt")
```
指令集选项可与前面的编译优化组合，但必须确认目标 CPU 支持，不能因为本机支持就默认评测机也支持
#### 局部函数优化
当只需要优化特定函数时，可以使用 `push_options` / `pop_options`，避免影响其他代码
```cpp
#pragma GCC push_options
#pragma GCC optimize("O3")
#pragma GCC target("avx2,popcnt")

void work() {
    // 需要优化的函数
}

#pragma GCC pop_options
```
以上 pragma 对后续定义的函数生效，`pop_options` 恢复之前的设置
#### 注意事项
- GCC 的 `O3` 包含 `O2` 的优化，但更激进不代表运行速度一定更快
- `Ofast` 会启用 `-ffast-math` 等选项，可能改变浮点运算、NaN、无穷大及有符号零等行为，不能作为通用默认配置
- `target` 指令集优化通常面向特定架构，AVX2、BMI 等属于 x86 指令集，不适用于所有平台
- 未支持的 CPU 执行相应指令可能触发 `Illegal instruction`
- 指令集优化只是允许编译器使用对应指令，不代表程序一定会自动向量化
- 对于单文件程序，编译优化优先使用命令行选项；`#pragma` 适合不能修改评测机编译参数时尝试
- 不建议使用 `#pragma GCC optimize("trapv")` 等与加速无关的选项来卡常
#### 常见用法
##### 本地对比优化等级
```
g++ main.cpp -std=gnu++20 -O2 -o main
g++ main.cpp -std=gnu++20 -O3 -o main
g++ main.cpp -std=gnu++20 -O3 -flto -o main
```
`-flto` 启用链接时优化，单文件竞赛程序的收益不一定明显，测试时仍需保证相同数据、运行环境及正确输出
##### C++20 分支预测提示
```cpp
if (x == 0) [[unlikely]] {
    // 极少发生的情况
} else {
    // 常见情况
}
```
`[[likely]]` 与 `[[unlikely]]` 是 C++20 属性，只提供分支概率提示，不保证生成更快的代码
#### 代码层面的常用优化
- 减少重复分配：已知元素个数时提前 `reserve(n)`，可减少扩容
- 改善局部性：连续数组通常比大量离散分配的节点更有缓存优势
- 避免不必要的复制：大对象传参优先考虑 `const T &`
- 减少高频操作开销：循环中避免重复执行不变的计算或构造临时对象
- 选择合适的 I/O：大量输入输出优先使用快速 I/O
