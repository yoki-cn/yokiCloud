### 时间线段树分治与可撤销维护
---
#### 时间线段树
```cpp
template<class E>
struct TimeSeg {
    int q, base{ 1 };
    vector<vector<E>> seg;
    explicit TimeSeg(int q_) : q(q_) {
        while (base < q) base <<= 1;
        seg.resize(base << 1);
    }
    // ===== 基础接口：将事件加入整个生效区间 [l, r) =====
    void add(int l, int r, const E &e) {
        if (l >= r) return;
        for (l += base, r += base; l < r; l >>= 1, r >>= 1) {
            if (l & 1) seg[l ++].push_back(e);
            if (r & 1) seg[-- r].push_back(e);
        }
    }
private:
    // ===== 核心 DFS：进入节点应用事件，退出节点恢复快照 =====
    template<class State, class Apply, class F>
    void run(int p, State &st, Apply &apply, F &answer) {
        auto snap{ st.snapshot() };
        for (const auto &e : seg[p]) apply(st, e);

        if (p >= base) {
            int t{ p - base };
            if (t < q) answer(t, st);
        } else {
            run(p << 1, st, apply, answer);
            run(p << 1 | 1, st, apply, answer);
        }

        st.rollback(snap);
    }
public:
    template<class State, class Apply, class F>
    void run(State &st, Apply apply, F answer) {
        if (q) run(1, st, apply, answer);
    }
};
```
##### 成员变量
- `q`：时间点数量，时间为 `0 ... q - 1`
- `base`：不小于 `q` 的最小二次幂
- `seg[p]`：在线段树节点 `p` 对应整个时间区间内始终有效的事件
##### 接口
- `TimeSeg<E>(q)`：建立时间线段树，事件类型为 `E`
- `add(l, r, e)`：事件 `e` 在整个 `[l,r)` 内有效，$O(\log q)$
- `run(st, apply, answer)`：遍历所有时间点
- `apply(st, e)`：将事件 `e` 加入当前可撤销状态
- `answer(t, st)`：回答时间 `t` 的询问
传入的 `State` 至少需要提供
```cpp
auto snapshot() const;
void rollback(/* snapshot 返回的类型 */ snap);
```
`snapshot()` 的返回类型不限，只需能够传回对应的 `rollback()`
##### 时间定义
推荐统一定义：
> 时间 `t` 表示第 `t` 个操作执行后的状态

若对象在时间 `l` 加入，在时间 `r` 删除，并且删除操作执行后立即失效，则生命周期为
$$
[l,r)
$$
因此
- 时间 `l` 包含该对象
- 时间 `r` 不包含该对象
如果题目询问的是**操作执行前**的状态，需要相应平移生命周期端点
##### 常见用法
已知所有事件生命周期
```cpp
struct E {
    int x;
};
TimeSeg<E> seg(q);
for (auto [l, r, x] : intervals) {
    seg.add(l, r, { x });
}
State st;
seg.run(st,
    [&](State &cur, const E &e) {
        cur.add(e.x);
    },
    [&](int t, State &cur) {
        // cur 恰好表示时间 t 的状态
    }
);
```
##### 注意事项
- 这是离线算法，运行前必须得到每个事件完整的生效区间
- 时间线段树只负责**调度事件生命周期**，不负责具体维护内容
- `apply()` 可以是并查集合并、加入异或约束、插入线性基或其他可撤销操作
- `run()` 已经负责节点级 `snapshot()` / `rollback()`，回调中通常不要自行回滚
- 状态必须支持撤销，不能直接使用只支持永久修改的数据结构
- 所有时间区间统一为 `[l,r)`
- 要求 `0 <= l <= r <= q`
- `q = 0` 时不会调用 `answer()`
- 时间线段树与普通线段树不同，不维护区间聚合信息，只利用线段树把一个生命周期拆成 $O(\log q)$ 个节点
- DFS 深度仅为 $O(\log q)$
##### 复杂度
设共有 $m$ 个生命周期区间
每个 `[l,r)` 被拆成 $O(\log q)$ 个节点，因此事件记录数为
$$
O(m\log q)
$$
若单次 `apply()` 代价为 $A$，对应撤销总代价与修改量同阶，则总时间为
$$
O(q+m\log q\cdot A)
$$
不计状态自身空间时，时间线段树空间为
$$
O(q+m\log q)
$$
#### 生命周期预处理
当输入给出的是
```text
加入对象
删除对象
```
而不是直接给 `[l,r)` 时，可以先把操作转换成生命周期
下面的 `Life` 对任意可排序的对象类型都适用
```cpp
template<class T>
struct Life {
    struct Seg {
        int l, r;
        T x;
    };
    struct State {
        int cnt{}, l{};
    };
    vector<Seg> segs;
    map<T, State> opened;
    // ===== 生命周期维护 =====
    void add(int t, const T &x) {
        auto &s{ opened[x] };
        if (s.cnt ++ == 0) s.l = t;
    }
    void erase(int t, const T &x) {
        auto it{ opened.find(x) };
        auto &[cnt, l]{ it->second };
        if (-- cnt) return;
        if (l < t) segs.push_back({ l, t, x });
        opened.erase(it);
    }
    // ===== 收尾：读取完全部操作后调用 =====
    void close_all(int q) {
        for (auto &[x, s] : opened) {
            if (s.l < q) segs.push_back({ s.l, q, x });
        }
        opened.clear();
    }
};
```
##### 接口说明
- `add(t, x)`：时间 `t` 增加一份对象 `x`
- `erase(t, x)`：时间 `t` 删除一份对象 `x`
- `close_all(q)`：将操作结束后仍然存在的对象补为 `[l,q)`
- `segs`：所有生成的 `{l,r,x}` 生命周期
##### 注意事项
- `T` 需要支持 `operator<`，以便作为 `map` 的键
- `erase()` 要求删除前至少存在一份对应对象
- 当前实现按**多重集合语义**维护出现次数
- `0 -> 1` 时开始生命周期
- `1 -> 0` 时结束生命周期
- 中间的重复加入、删除不会产生重叠区间
- 若题目为普通集合语义，重复加入已存在对象应当无效，需要在读入阶段过滤
- 若对象具有等价表示，应先规范化后再交给 `Life`
例如无向边需要保证
```cpp
auto edge = [](int u, int v) {
    if (u > v) swap(u, v);
    return array{ u, v };
};
```
#### 动态连通性
依赖 **3.2.6 可撤销 DSU**
##### 完整增删边与连通性询问
```cpp
using Edge = array<int, 2>;
auto edge = [](int u, int v) {
    if (u > v) swap(u, v);
    return Edge{ u, v };
};
Life<Edge> life;
for (int t = 0; t < q; ++ t) {
    if (op[t] == '+') {
        life.add(t, edge(u[t], v[t]));
    } else if (op[t] == '-') {
        life.erase(t, edge(u[t], v[t]));
    }
}
life.close_all(q);
TimeSeg<Edge> seg(q);
for (auto &[l, r, e] : life.segs) {
    seg.add(l, r, e);
}
RollbackDSU dsu(n);
vector<bool> ans(q);
seg.run(dsu,
    [](RollbackDSU &cur, const Edge &e) {
        cur.unite(e[0], e[1]);
    },
    [&](int t, RollbackDSU &cur) {
        if (op[t] == '?') {
            ans[t] = cur.same(u[t], v[t]);
        }
    }
);
for (int t = 0; t < q; ++ t) {
    if (op[t] == '?') {
        cout << (ans[t] ? "YES\n" : "NO\n");
    }
}
```
##### 已知边生命周期
若题目已经直接给出
```text
[l,r) : 边 (u,v) 存在
```
则 `Life` 可以直接删除
```cpp
using Edge = array<int, 2>;

TimeSeg<Edge> seg(q);
for (auto [l, r, u, v] : intervals) {
    seg.add(l, r, { u, v });
}

RollbackDSU dsu(n);

seg.run(dsu,
    [](RollbackDSU &cur, const Edge &e) {
        cur.unite(e[0], e[1]);
    },
    [&](int t, RollbackDSU &cur) {
        // 查询时间 t 的图
    }
);
```
##### 可维护的信息
除 `same(u,v)` 外，只要可撤销 DSU 本身维护了相应信息，同一个框架还可以回答
```text
当前连通块数量
u 所在连通块大小
u、v 是否连通
加入边后是否发生合并
```
##### 复杂度
设生命周期数量为 $m$，连通性询问数量为 $k$
每条生命周期被加入 $O(\log q)$ 个时间线段树节点，因此执行
$$
O(m\log q)
$$
次合并
若可撤销 DSU 使用按大小合并且不路径压缩，则树高为 $O(\log n)$，单次 `find / unite / same` 为 $O(\log n)$
总时间复杂度
$$
O\left(q+m\log q\log n+k\log n\right)
$$
若使用 `Life` 的 `map` 处理 $q$ 次增删操作，还需要
$$
O(q\log q)
$$
量级的预处理时间
总空间复杂度
$$
O(n+q+m\log q)
$$
#### 动态二分图与异或关系
动态二分图并不是另一套时间线段树
对于无向边 `(u,v)`，二分图约束等价于
$$
col_u\oplus col_v=1
$$
因此只需把事件从普通边
```cpp
struct Edge {
    int u, v;
};
```
扩展为关系约束
```cpp
struct E {
    int u, v, w;
};
```
其中
```text
w = 0 : u、v 关系相同
w = 1 : u、v 关系不同
```
然后使用 **3.2.8 可撤销异或关系与二分图 DSU** 作为状态
时间线段树部分完全不变
```cpp
TimeSeg<E> seg(q);
for (auto [l, r, u, v, w] : intervals) {
    seg.add(l, r, { u, v, w });
}
RollbackXorDSU dsu(n);
vector<bool> ans(q);
seg.run(dsu,
    [](auto &cur, const E &e) {
        cur.add_relation(e.u, e.v, e.w);
    },
    [&](int t, auto &cur) {
        ans[t] = cur.valid();
    }
);
```
这里不重复实现关系 DSU，核心要求是：
- 父子关系变化可以撤销
- 异或势能变化可以撤销
- 冲突数量或合法状态也必须可以撤销
- `snapshot()` 后发生的所有状态变化都必须能由 `rollback()` 恢复
> [!tip]
> 动态二分图中每条普通边直接视为 `w = 1` 的异或约束即可
#### 其他可撤销维护
时间线段树要求的并不是“必须使用 DSU”，而只是状态满足
```cpp
snapshot()
apply(event)
rollback(snapshot)
```
因此可以替换成其他可撤销结构

| 状态结构 | 常见用途 |
|---|---|
| 可撤销 DSU | 动态连通性、连通块统计 |
| 可撤销异或 / 带权 DSU | 动态二分图、异或关系、势能约束 |
| 可撤销线性基 | 动态最大异或、线性可表示性 |
| 可撤销计数结构 | 生命周期集合统计 |
| 自定义历史栈 | 其他区间生效的动态状态 |
#### 自定义可撤销状态骨架
若状态比较简单，不必专门设计持久化结构，只需要记录每次修改前的信息
```cpp
struct State {
    struct Change {
        // 恢复本次修改所需的信息
    };
    vector<Change> his;
    int snapshot() const {
        return his.size();
    }
    void add(/* event */) {
        // his.push_back(...)
        // 修改当前状态
    }
    void rollback(int snap) {
        while (int(his.size()) > snap) {
            auto c{ his.back() };
            his.pop_back();
            // 根据 c 恢复状态
        }
    }
};
```
##### 注意事项
- 不要为了撤销而复制整个状态，通常只记录真正被修改的字段
- `snapshot()` 通常就是历史栈大小
- 一次 `apply()` 修改多个位置时，需要完整记录这些修改
- “什么都没有改变”的操作是否需要压入历史，要和 `rollback()` 的实现保持一致
- 若维护额外全局量，例如连通块数、冲突数、答案值，也必须一起恢复
- 可撤销结构通常不能使用无法恢复的路径压缩
- 按大小 / 按秩合并非常适合与 rollback 搭配
#### 初始始终有效的事件
若某个约束从最开始就存在，并在全部时间内有效
```cpp
seg.add(0, q, e);
```
若初始图已有边，同样可以直接加入 `[0,q)`
如果它之后会被删除，则应将其生命周期设为
```text
[0, erase_time)
```
而不是同时再通过 `Life::add(0, e)` 重复加入
#### 时间端点常见情况
设第 `t` 个操作发生在时间 `t`

| 操作含义 | 生命周期处理 |
|---|---|
| `t` 时加入，操作后立即生效 | 左端点为 `t` |
| `t` 时删除，操作后立即失效 | 右端点为 `t` |
| 查询操作后的状态 | 直接查询时间 `t` |
| 查询操作前的状态 | 需要调整时间定义或将询问平移 |
| 初始已存在 | 左端点为 `0` |
| 操作结束仍存在 | `close_all(q)` 补到 `q` |
最容易写错的不是线段树本身，而是这里的时间定义
#### 与其他算法的区别

| 方法 | 事件模型 | 核心操作 |
|---|---|---|
| 带修改莫队 | 修改与查询混合，时间指针前后移动 | 应用 / 撤销单次修改 |
| CDQ 分治 | 过去事件向未来事件产生贡献 | 左半贡献右半 |
| 时间线段树分治 | 对象在一段时间内持续有效 | 区间挂事件 + DFS 回滚 |
| 可持久化结构 | 需要保留并访问多个版本 | 保存版本而不是撤销 |
如果题目中反复出现
```text
加入 x
删除 x
询问当前状态
```
并且能够离线，就应优先检查：
```text
x 的存在时间能否拆成若干 [l,r)
        ↓
状态能否 snapshot + rollback
        ↓
时间线段树分治
```
#### 复杂度总结
设
- `q`：时间点数量
- `m`：生命周期区间数量
- `A`：应用一个事件的复杂度
- `Q`：回答一个时间点询问的复杂度
则通用时间线段树复杂度为

| 操作 | 时间复杂度 |
|---|---|
| 构造 | $O(q)$ |
| 单个 `add(l,r,e)` | $O(\log q)$ |
| 存储全部生命周期 | $O(m\log q)$ |
| DFS 应用全部事件 | $O(m\log q\cdot A)$ |
| 回答全部时间点 | $O(qQ)$ |
因此总时间复杂度为
$$
O\left(q+m\log q\cdot A+qQ\right)
$$
空间复杂度为
$$
O(q+m\log q+S)
$$
其中 $S$ 为可撤销状态及其历史栈空间
