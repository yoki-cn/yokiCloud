### 动态开点线段树
---
```cpp
template<class Info, class Coord = i64>
struct DynamicSegTree {
    struct Node {
        int ch[2]{};
        Info info{};
    };
    Coord lo, hi;
    vector<Node> tr{ Node{} };
    int root{ 0 };
    explicit DynamicSegTree(Coord lo_, Coord hi_, size_t reserve_nodes = 0) : lo(lo_), hi(hi_) {
        assert(lo < hi);
        if (reserve_nodes) tr.reserve(reserve_nodes + 1);
    }
    // ===== 节点创建与维护：modify / query 依赖，不建议删除 =====
    int new_node() {
        tr.emplace_back();
        return int(tr.size()) - 1;
    }
    const Info &info(int p) const {
        static const Info e{};
        return p ? tr[p].info : e;
    }
    void pull(int p) {
        tr[p].info = info(tr[p].ch[0]) + info(tr[p].ch[1]);
    }
    // ===== 单点修改：modify() 为通用叶子修改，set() 为覆盖赋值 =====
    template<class F>
    int modify(int p, Coord l, Coord r, Coord x, F &f) {
        if (!p) p = new_node();
        if (l + 1 == r) {
            f(tr[p].info);
            return p;
        }
        Coord m = midpoint(l, r);
        int d = x >= m;
        int q = modify(tr[p].ch[d], d ? m : l, d ? r : m, x, f);
        tr[p].ch[d] = q;
        pull(p);
        return p;
    }
    template<class F>
    void modify(Coord x, F &&f) {
        assert(lo <= x && x < hi);
        root = modify(root, lo, hi, x, f);
    }
    void set(Coord x, const Info &v) {
        modify(x, [&](Info &a) { a = v; });
    }
    // ===== 查询：未创建节点视为 Info{}，查询不会创建新节点 =====
    Info query(int p, Coord l, Coord r, Coord ql, Coord qr) const {
        if (!p || qr <= l || r <= ql) return Info{};
        if (ql <= l && r <= qr) return tr[p].info;
        Coord m = midpoint(l, r);
        return query(tr[p].ch[0], l, m, ql, qr) + query(tr[p].ch[1], m, r, ql, qr);
    }
    Info query(Coord l, Coord r) const {
        assert(lo <= l && l <= r && r <= hi);
        return query(root, lo, hi, l, r);
    }
    Info get(Coord x) const {
        assert(lo <= x && x < hi);
        return query(x, x + 1);
    }
    const Info &all() const { return info(root); }
    int nodes() const { return int(tr.size()) - 1; }
};
```
#### 接口说明
##### 模板参数与成员
* `Info`：节点维护的信息类型，要求 `Info{}` 为合并单位元，并定义 `Info + Info`
* `Coord`：坐标类型，默认 `i64`
* `[lo, hi)`：整棵线段树维护的整数值域
* `root`：根节点编号，`0` 表示空树
* `tr`：节点池，`tr[0]` 为哨兵空节点
##### 接口
* `DynamicSegTree(lo, hi, reserve_nodes = 0)`：维护整数值域 `[lo, hi)`；第三个参数可预留节点空间，构造本身 $O(1)$
* `modify(x, f)`：对位置 `x` 的叶节点执行 `f(Info&)`，$O(\log(hi-lo))$
* `set(x, v)`：令位置 `x` 的信息变为 `v`，$O(\log(hi-lo))$
* `query(l, r)`：查询 `[l, r)` 的合并信息，$O(\log(hi-lo))$
* `get(x)`：查询单点 `x`，$O(\log(hi-lo))$
* `all()`：返回整棵树的信息，$O(1)$
* `nodes()`：当前实际创建的节点数，$O(1)$
#### 注意事项
* 坐标和值域均采用**整数左闭右开区间** `[l, r)`
* 没有 `build()`；只有访问到的修改路径才会创建节点
* `Info{}` 必须是合并单位元，即应满足：
```cpp
Info{} + x == x
x + Info{} == x
```
因此未开点区域天然表示“默认空信息”
* `query()` **不会开点**。只有 `modify()` / `set()` 会增加节点
* 当前版本删除一个值后，即使节点重新变成 `Info{}`，也**不会释放已经创建的节点**。节点回收留到之后的“可合并权值线段树”统一处理
* 不支持区间修改，因此没有 `Tag / apply / push`。动态开点 + lazy 是另一层扩展，不建议让基础板子变臃肿
* 使用 `midpoint(l, r)` 而不是 `(l + r) / 2`，避免大坐标时 `l + r` 溢出
* 一次修改最多创建树高数量的新节点，因此可根据操作数提前：
```cpp
seg.tr.reserve(...);
```
更推荐直接通过构造函数的 `reserve_nodes` 参数完成
#### 常见用法
##### 区间和
```cpp
struct Info {
    i64 sum{};
};
Info operator+(const Info &a, const Info &b) {
    return { a.sum + b.sum };
}
```
建立一个巨大值域：
```cpp
DynamicSegTree<Info> seg(-1E18, i64(1E18) + 1);
```
单点加：
```cpp
seg.modify(x, [&](Info &a) { a.sum += v; });
```
区间和：
```cpp
i64 ans = seg.query(l, r).sum;
```
即查询 `[l, r)`
##### 单点覆盖
```cpp
seg.set(x, { v });
```
等价于：
```cpp
seg.modify(x, [&](Info &a) { a = { v }; });
```
##### 动态维护出现次数
```cpp
struct Info {
    int cnt{};
};
Info operator+(const Info &a, const Info &b) {
    return { a.cnt + b.cnt };
}
```
插入 / 删除一个值：
```cpp
seg.modify(x, [&](Info &a) { ++ a.cnt; });
seg.modify(x, [&](Info &a) { -- a.cnt; });
```
查询某个值域内元素数量：
```cpp
int cnt = seg.query(l, r).cnt;
```
不过如果进一步需要：
```text
kth
rank
前驱 / 后继
merge
split
```
就不要继续膨胀这一份板子了，那些统一放到之后的 **可合并权值线段树**
##### 估算预留节点数
若有 `q` 次单点修改、值域树高约为 `B`：
```cpp
DynamicSegTree<Info> seg(0, 1LL << 60, size_t(q) * 61);
```
这是一个保守上界；不同修改路径通常会共享节点，所以实际节点数一般更少
#### 复杂度
设值域宽度为
$$W=hi-lo$$

| 操作                                         |      时间复杂度 |
| ------------------------------------------ | ---------: |
| 构造                                         |     `O(1)` |
| `modify()` / `set()` / `get()` / `query()` | `O(log W)` |
| `all()`                                    |     `O(1)` |
若进行了 `q` 次单点修改，空间复杂度最坏为
$$O(q\log W)$$
而不是普通线段树的 $O(W)$
