### 图上博弈与对抗搜索
---
#### 图上胜负与平局逆推
---
在有向状态图上双方轮流沿一条出边移动。默认无法行动者输；若双方都能避免失败并无限进行，则为平局
```cpp
struct GameGraph {
    enum { LOSE = -1, DRAW = 0, WIN = 1, UNK = 2 };
    int n;
    vector<vector<int>> g, rg;
    vector<int> ini, st, go;
    explicit GameGraph(int n_) : n(n_), g(n), rg(n), ini(n, UNK), st(n), go(n, -1) {}
    void add(int u, int v) {
        g[u].push_back(v);
        rg[v].push_back(u);
    }
    void fix(int u, int s) { ini[u] = s; }
    void solve() {
        vector<int> rem(n);
        queue<int> q;
        fill(st.begin(), st.end(), DRAW);
        fill(go.begin(), go.end(), -1);
        for (int u = 0; u < n; ++ u) {
            rem[u] = g[u].size();
            if (ini[u] != UNK) {
                st[u] = ini[u];
                q.push(u);
            } else if (!rem[u]) {
                st[u] = LOSE;
                q.push(u);
            }
        }
        while (!q.empty()) {
            int v = q.front();
            q.pop();
            for (int u : rg[v]) if (st[u] == DRAW) {
                if (st[v] == LOSE) {
                    st[u] = WIN;
                    go[u] = v;
                    q.push(u);
                } else if (-- rem[u] == 0) {
                    st[u] = LOSE;
                    q.push(u);
                }
            }
        }
        for (int u = 0; u < n; ++ u) if (ini[u] == UNK && go[u] == -1) {
            if (st[u] == DRAW) {
                for (int v : g[u]) if (st[v] == DRAW) {
                    go[u] = v;
                    break;
                }
            } else if (!g[u].empty()) {
                go[u] = g[u][0];
            }
        }
    }
};
```
##### 接口说明
- `GameGraph(n)`：建立 `n` 个状态，编号为 `0..n-1`
- `add(u,v)`：当前玩家可从状态 `u` 移动到状态 `v`
- `fix(u,s)`：预先指定状态 `u` 为 `WIN` 或 `LOSE`
- `solve()`：求所有状态的胜负和平局情况
- `st[u]`：
  - `WIN`：当前玩家必胜
  - `LOSE`：当前玩家必败
  - `DRAW`：双方最优策略下均可避免失败，但无法强制获胜
- `go[u]`：一种最优后继状态；终止状态为 `-1`
##### 注意事项
核心递推只有三条：
- 存在一个后继为 `LOSE`，当前状态就是 `WIN`
- 所有后继都是 `WIN`，当前状态就是 `LOSE`
- 最终仍不能确定的状态就是 `DRAW`
模板从已确定状态沿反图逆推。`rem[u]` 表示尚未被证明为 `WIN` 的后继数量；当所有后继都已确定为 `WIN` 时，`u` 才能确定为 `LOSE`
`st[u]` 始终表示**轮到当前玩家行动时**的结果。若两名玩家可执行的操作不同，应把“轮到谁”也放入状态：
```cpp
id = u * 2 + turn;
```
`fix(u,s)` 同样从状态中“当前玩家”的角度定义。例如某玩家走到目标点后立刻获胜，而状态已经切换给另一玩家，则该目标状态对新的当前玩家应标为 `LOSE`
默认所有出度为 `0` 且未 `fix` 的状态都是 `LOSE`
无限循环只有在题目规定其结果为平局时才能直接使用该模板。若重复局面判负、存在步数限制或超时判定，应把对应信息加入状态
这里求的是 `WIN / LOSE / DRAW`，**不是 SG 值**。不能利用结果异或合并多个独立游戏；独立公平组合游戏仍使用 `13.3` 的 SG 定理
##### 常见用法
普通“无路可走者输”的图上博弈：
```cpp
GameGraph game(n);
for (auto [u, v] : edges) game.add(u, v);
game.solve();

if (game.st[s] == GameGraph::WIN) {
    int v = game.go[s];
} else if (game.st[s] == GameGraph::LOSE) {
    // 后手必胜
} else {
    // 平局
}
```
双方移动规则不同：
```cpp
GameGraph game(2 * n);
auto id = [&](int u, int t) {
    return 2 * u + t;
};

for (int u = 0; u < n; ++ u) {
    for (int v : g0[u]) game.add(id(u, 0), id(v, 1));
    for (int v : g1[u]) game.add(id(u, 1), id(v, 0));
}
game.solve();
```
预设特殊终止状态：
```cpp
game.fix(u, GameGraph::WIN);
game.fix(v, GameGraph::LOSE);
game.solve();
```
##### 复杂度
- 建图：$O(V+E)$
- `solve()`：$O(V+E)$
- 空间：$O(V+E)$
#### Alpha-Beta 对抗搜索
---
用于双人、零和、完全信息的有限深度对抗搜索。使用 Negamax 统一双方逻辑，并在 Minimax 基础上加入 Alpha-Beta 剪枝
```cpp
template<class S, class F, class G, class A, class U>
i64 ab(S &s, int dep, i64 l, i64 r, F f, G gen, A ap, U un) {
    auto dfs = [&](auto &&self, int d, i64 a, i64 b) -> i64 {
        if (d <= 0) return f(s);
        auto ops = gen(s);
        if (ops.empty()) return f(s);
        for (auto &op : ops) {
            ap(s, op);
            i64 v = -self(self, d - 1, -b, -a);
            un(s, op);
            a = max(a, v);
            if (a >= b) break;
        }
        return a;
    };
    return dfs(dfs, dep, l, r);
}
```
##### 接口说明
- `ab(s,dep,l,r,f,gen,ap,un)`：全窗口时返回当前玩家视角下的最优估值；窄窗口可能只返回上/下界，不能无条件当精确值缓存
- `s`：当前状态，搜索过程中原地修改
- `dep`：剩余搜索深度
- `[l,r)`：当前 Alpha-Beta 搜索窗口
- `f(s)`：返回当前状态对**当前玩家**的估值
- `gen(s)`：返回当前状态所有可执行操作
- `ap(s,op)`：执行操作，并切换到对手行动的状态
- `un(s,op)`：撤销操作
- 根节点通常使用足够大的窗口 `[-INF,INF]`；l<r，边界和估值必须可安全取负（不能为 i64 最小值），所有真实估值宜严格位于全窗口内部；dep<=0 直接评估
##### 注意事项
Negamax 利用零和博弈的关系
$$
V(s)=-V(\operatorname{next}(s))
$$
因此不需要分别写 `max()` 和 `min()`
`f(s)` 必须始终从**当前行动玩家**的角度估值：
- 越大越有利
- 越小越不利
- 双方视角互为相反数
搜索窗口中：
- `a`：当前至少能够取得的分数
- `b`：对手不会允许当前玩家达到的上界
- 当 `a >= b` 时，剩余分支已经不可能影响祖先决策，可以直接剪枝
操作顺序不会影响正确性，但会极大影响速度。应优先搜索更可能优秀的操作，例如：
- 上一轮搜索得到的最优操作
- 吃子、得分等强制操作
- 启发式估值较高的操作

若有明确终局，应让 `gen(s)` 返回空操作，并由 `f(s)` 返回准确的终局分数。终局分数通常应远大于普通局面估值
常见写法：
```cpp
WIN - step
```
比固定返回 `WIN` 更好，可以让算法优先选择更快获胜；失败时对应：
```cpp
-WIN + step
```
从而尽量延迟失败
若相同局面会通过多条路径反复到达，可以加入置换表。但 **Alpha-Beta 剪枝得到的返回值不一定是精确值**，不能无条件直接记忆化。标准置换表需要区分：
- `EXACT`：精确值
- `LOWER`：下界
- `UPPER`：上界
即使本节点遍历了全部操作，也可能因未超过传入 alpha 而只返回界，不能仅凭“未剪枝”当成 EXACT。以进入节点时的窗口 [a0,b0) 分类：返回值 <=a0 为 UPPER，>=b0 为 LOWER，严格落在窗口内部才可标为 EXACT；缓存还需区分搜索深度和局面状态。
迭代加深常与 Alpha-Beta 配合：
```cpp
for (int dep = 1; dep <= lim; ++ dep) {
    ans = ab(s, dep, -INF, INF, f, gen, ap, un);
}
```
上一层得到的最优操作可以用于下一层的操作排序，通常能显著加强剪枝
##### 常见用法
基本调用：
```cpp
constexpr i64 INF{ numeric_limits<i64>::max() };

auto f = [&](const State &s) -> i64 {
    return eval(s);
};

auto gen = [&](const State &s) {
    vector<int> ops;
    // 生成并尽量按优秀程度排序
    return ops;
};

auto ap = [&](State &s, int op) {
    s.apply(op);
};

auto un = [&](State &s, int op) {
    s.undo(op);
};

i64 ans = ab(s, dep, -INF, INF, f, gen, ap, un);
```

需要求根节点的最优操作时（dep>=1；终局 ops 为空时 bop=-1）：
```cpp
i64 best = -INF;
int bop = -1;
auto ops = gen(s);
for (int op : ops) {
    ap(s, op);
    i64 v = -ab(s, dep - 1, -INF, -best, f, gen, ap, un);
    un(s, op);
    if (bop == -1 || v > best) {
        best = v;
        bop = op;
    }
}
```

若不想利用根节点已有的 `best` 缩小窗口，也可直接写：
```cpp
i64 v = -ab(s, dep - 1, -INF, INF, f, gen, ap, un);
```
代码更直观，但剪枝略弱。

##### 复杂度
设平均分支数为 $b$，搜索深度为 $d$：
- Minimax 最坏时间复杂度：$O(b^d)$
- Alpha-Beta 最坏时间复杂度仍为 $O(b^d)$
- 操作顺序理想时约为 $O(b^{d/2})$
- 递归空间：$O(d)$，不计状态本身与每层生成的操作
