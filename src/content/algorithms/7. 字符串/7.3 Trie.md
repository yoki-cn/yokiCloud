### Trie
---
```cpp
template<int A = 26, int offset = 'a'>
struct Trie {
    struct Node {
        array<int, A> next{};
        int pass{ 0 }, cnt{ 0 };
    };
    vector<Node> t;
    explicit Trie(int m = 0) {
        t.reserve(m + 1);
        t.emplace_back();
    }
    // ===== 基础函数：以下代码被所有接口依赖，不建议删除 =====
    template<class T>
    static int id(const T &c) { return int(c) - offset; }
    int new_node() {
        t.emplace_back();
        return int(t.size()) - 1;
    }
    // ===== 基础接口：插入 / 查找 / 单步转移 =====
    template<class Seg>
    int add(const Seg &s) {
        int p{ 0 };
        ++ t[p].pass;
        for (const auto &c : s) {
            int x{ id(c) };
            if (!t[p].next[x]) t[p].next[x] = new_node();
            p = t[p].next[x];
            ++ t[p].pass;
        }
        ++ t[p].cnt;
        return p;
    }
    template<class Seg>
    int find(const Seg &s) const {
        int p{ 0 };
        for (const auto &c : s) {
            p = t[p].next[id(c)];
            if (!p) return -1;
        }
        return p;
    }
    template<class T>
    int step(int p, const T &c) const {
        if (p < 0) return -1;
        int q{ t[p].next[id(c)] };
        return q ? q : -1;
    }
    int size() const { return int(t.size()); }
    int total() const { return t[0].pass; }
    // ===== 查询接口：若只建 Trie 后自行 DP / DFS，可按需删除 =====
    template<class Seg>
    int count(const Seg &s) const {
        int p{ find(s) };
        return p == -1 ? 0 : t[p].cnt;
    }
    template<class Seg>
    bool contains(const Seg &s) const { return count(s) > 0; }
    // 当前有多少字符串以 s 为前缀
    template<class Seg>
    int prefix_count(const Seg &s) const {
        int p{ find(s) };
        return p == -1 ? 0 : t[p].pass;
    }
    // 枚举当前字典中所有作为 s 前缀的字符串终止节点
    template<class Seg, class F>
    void match_prefixes(const Seg &s, F f) const {
        int p{ 0 };
        if (t[p].cnt) f(p);
        for (const auto &c : s) {
            p = t[p].next[id(c)];
            if (!p) return;
            if (t[p].cnt) f(p);
        }
    }
    // 当前有多少已存字符串是 s 的前缀
    template<class Seg>
    int count_prefixes(const Seg &s) const {
        int ans{ 0 };
        match_prefixes(s, [&](int p) {
            ans += t[p].cnt;
        });
        return ans;
    }
    // ===== 删除接口：若不需要删除字符串，可直接删除 =====
    // 只修改 pass / cnt，不回收节点或删除边
    template<class Seg>
    bool erase(const Seg &s) {
        int p{ find(s) };
        if (p == -1 || !t[p].cnt) return false;
        -- t[p].cnt;
        p = 0;
        -- t[p].pass;
        for (const auto &c : s) {
            p = t[p].next[id(c)];
            -- t[p].pass;
        }
        return true;
    }
};
```
#### 成员变量
- `t[0]`：根节点，表示空前缀
- `t[u].next[c]`：节点 `u` 沿字符编号 `c` 的儿子，`0` 表示不存在
- `t[u].pass`：当前仍存在且经过节点 `u` 的字符串数量
- `t[u].cnt`：当前仍存在且恰好在节点 `u` 结束的字符串数量
因此：
$$t[0].pass=\text{当前字符串总数}$$
对于非根节点 `u`：
> `t[u].pass` 同时等于 Trie 中以该节点前缀开头的字符串多重集合大小
#### 基础接口
- `Trie(m)`：构造 Trie，`m` 为预计插入的总字符数，仅用于 `reserve`
- `add(s)`：插入一次字符串 `s`，返回终止节点，$O(|s|)$
- `find(s)`：返回 `s` 对应的 Trie 节点，不存在返回 `-1`，$O(|s|)$
- `step(p,c)`：从节点 `p` 沿字符 `c` 走一步，不存在返回 `-1`，$O(1)$
- `size()`：返回历史创建过的 Trie 节点总数，$O(1)$
- `total()`：返回当前字符串多重集合大小，$O(1)$
#### 查询接口
- `count(s)`：返回字符串 `s` 当前出现次数，$O(|s|)$
- `contains(s)`：判断当前是否存在字符串 `s`，$O(|s|)$
- `prefix_count(s)`：返回当前有多少字符串以 `s` 为前缀，$O(|s|)$
- `match_prefixes(s,f)`：枚举当前字典中所有是 `s` 前缀的字符串终止节点，$O(|s|)$
- `count_prefixes(s)`：返回当前有多少已存字符串是 `s` 的前缀，$O(|s|)$
- `erase(s)`：删除一次 `s`，不存在则返回 `false`，$O(|s|)$
注意两种容易混淆的查询：
```text
prefix_count(s)   ：s 是多少字符串的前缀
count_prefixes(s) ：多少字符串是 s 的前缀
```
#### 注意事项
- 默认处理小写字母；大写字母使用 `Trie<26, 'A'>`
- 已经映射到 `[0,A)` 的整数序列使用 `Trie<A, 0>`
- 必须保证所有字符满足 `0 <= id(c) < A`
- `erase()` 不回收节点，也不会删除已经创建的 Trie 边，只维护 `pass / cnt`
- 因此删除后 `find(s)` 仍可能找到历史路径；判断当前字符串是否存在应使用 `count()` / `contains()`
- 同理，`step()` 可能走入当前 `pass == 0` 的历史节点；需要当前有效路径时应额外检查 `t[p].pass`
- `size()` 表示历史节点数，不表示当前有效前缀数
- `pass / cnt` 均按**字符串多重集合**统计，重复插入同一字符串会重复计数
- Trie 本身就是一棵以 `0` 为根的树；很多前缀、LCP 问题都可转成树上祖先、LCA 或子树问题
- 01 Trie、可持久化 01 Trie、Patricia Trie 等整数位结构应继续独立维护
#### 常见用法
##### 字符串计数与前缀计数
```cpp
int sum{ 0 };
for (auto &s : a) sum += s.size();
Trie<> tr(sum);
for (auto &s : a) {
    tr.add(s);
}
cout << tr.count("abc") << '\n';
cout << tr.prefix_count("ab") << '\n';
```
例如字典为：
```text
a
ab
ab
abc
b
```
则：
```cpp
tr.count("ab");          // 2
tr.prefix_count("ab");   // 3：ab, ab, abc
tr.count_prefixes("abc");// 4：a, ab, ab, abc
```
##### 枚举查询串的所有字典前缀
例如分词、前缀匹配：
```cpp
tr.match_prefixes(s, [&](int p) {
    // t[p].cnt > 0
    // 节点 p 对应的字典字符串是 s 的一个前缀
});
```
若需要区分每个前缀的长度，可以手写转移：
```cpp
int p{ 0 };
if (tr.t[p].cnt) {
    // 空串
}
for (int i = 0; i < int(s.size()); ++ i) {
    p = tr.step(p, s[i]);
    if (p == -1) break;
    if (tr.t[p].cnt) {
        // s[0..i] 是字典中的字符串
    }
}
```
##### 从文本某个位置开始沿 Trie 匹配
```cpp
int p{ 0 };
for (int r = l; r < int(s.size()); ++ r) {
    p = tr.step(p, s[r]);
    if (p == -1) break;
    if (tr.t[p].cnt) {
        // s[l..r] 是字典中的字符串
    }
}
```
这种写法常用于：
- 字典分词 DP
- Word Break
- 从每个位置枚举匹配模式
- Trie + 区间 / DP 转移
若文本和模式串规模都很大，且需要从大量位置反复开始匹配，通常应进一步考虑 AC 自动机
##### Trie 的树结构
每个非根节点唯一对应一个非空前缀
可以直接从 `next` 构造父亲和深度：
```cpp
vector<int> fa(tr.size(), -1);
vector<int> dep(tr.size());
for (int u = 0; u < tr.size(); ++ u) {
    for (int c = 0; c < A; ++ c) {
        int v{ tr.t[u].next[c] };
        if (!v) continue;
        fa[v] = u;
        dep[v] = dep[u] + 1;
    }
}
```
其中：
```cpp
dep[u]
```
就是节点 `u` 对应前缀的长度
##### 前缀关系 = Trie 祖先关系
设字符串 `a`、`b` 的终止节点分别为 `u`、`v`
则：
$$\boxed{ a\text{ 是 }b\text{ 的前缀} \iff u\text{ 是 }v\text{ 的 Trie 祖先} }$$
如果需要大量前缀关系查询，可以对 Trie 求 Euler 序：
```text
tin[u], tout[u]
```
于是：
$$u\text{ 是 }v\text{ 的祖先} \iff tin[u]\le tin[v]<tout[u]$$
##### 两个字符串的 LCP = Trie 上 LCA 深度
设字符串 `a`、`b` 的终止节点为 `u`、`v`
则：
$$\boxed{ \operatorname{LCP}(a,b) = dep[\operatorname{LCA}(u,v)] }$$
因为两个字符串共有的前缀，恰好对应两条根路径的公共部分
同理，对于多个字符串：
$$\boxed{ \operatorname{LCP}(S_1,S_2,\ldots,S_k) = dep[\operatorname{LCA}(pos_1,pos_2,\ldots,pos_k)] }$$
因此当题目同时涉及：
- 大量字符串
- 前缀关系
- 两两 LCP
- 路径 / 祖先查询
可以把字符串问题直接转成 Trie 树上的问题
##### 所有字符串两两 LCP 之和
对于当前 Trie 中的字符串多重集合：
$$\boxed{ \sum_{1\le i<j\le n} \operatorname{LCP}(S_i,S_j) = \sum_{u\ne0}\binom{pass[u]}2 }$$
代码：
```cpp
i64 ans{ 0 };
for (int u = 1; u < tr.size(); ++ u) {
    i64 x{ tr.t[u].pass };
    ans += x * (x - 1) / 2;
}
```
原因是：
一对字符串若 LCP 长度为 `k`，则它们恰好共同经过 Trie 上前 `k` 个非根节点，因此右侧恰好为这对字符串贡献 `k` 次
该公式在执行 `erase()` 后仍然成立，因为 `pass` 维护的是**当前**多重集合
##### LCP 恰好等于某个前缀的字符串对数
设节点 `u` 对应前缀 $P_u$
所有同时经过 `u` 的字符串对有：
$$\binom{pass[u]}2$$
若两字符串继续进入同一个儿子，则它们的 LCP 会更长
因此：
$$\boxed{ exact[u] = \binom{pass[u]}2 - \sum_{v\in child(u)} \binom{pass[v]}2 }$$
即 `exact[u]` 为：
> LCP 恰好等于节点 `u` 所对应前缀的字符串对数

```cpp
vector<i64> exact(tr.size());
for (int u = 0; u < tr.size(); ++ u) {
    i64 x{ tr.t[u].pass };
    exact[u] = x * (x - 1) / 2;
    for (int c = 0; c < A; ++ c) {
        int v{ tr.t[u].next[c] };
        if (!v) continue;
        i64 y{ tr.t[v].pass };
        exact[u] -= y * (y - 1) / 2;
    }
}
```
若再按 `dep[u]` 汇总，即可得到：
> LCP 长度恰好为 `k` 的字符串对数
##### 所有字符串长度之和
每个字符串长度为 `L` 时，会给其路径上的 `L` 个非根节点各贡献一次 `pass`
因此：
$$\boxed{ \sum_i |S_i| = \sum_{u\ne0}pass[u] }$$
代码：
```cpp
i64 sum_len{ 0 };
for (int u = 1; u < tr.size(); ++ u) {
    sum_len += tr.t[u].pass;
}
```
##### 前缀关系字符串对计数
###### 严格前缀
在节点 `u` 结束的字符串有：
```cpp
cnt[u]
```
个
在其子树中但不恰好结束于 `u` 的字符串有：
```cpp
pass[u] - cnt[u]
```
个
所以一个字符串是另一个字符串的**严格前缀**的无序字符串对数为：
$$\boxed{ \sum_u cnt[u]\bigl(pass[u]-cnt[u]\bigr) }$$
代码：
```cpp
i64 ans{ 0 };
for (int u = 0; u < tr.size(); ++ u) {
    ans += 1LL * tr.t[u].cnt * (tr.t[u].pass - tr.t[u].cnt);
}
```
###### 允许两个字符串相等
若把相同字符串也视作互为前缀，则再加：
$$\boxed{ \sum_u\binom{cnt[u]}2 }$$
##### 不同前缀数量
如果**从未删除字符串**，每个非根 Trie 节点都对应一个实际存在的不同非空前缀，因此：
```cpp
int distinct_prefixes = tr.size() - 1;
```
但是存在 `erase()` 时，死节点不会回收
此时：
- 历史创建过的不同非空前缀数：  
```cpp
tr.size() - 1
```
- 当前字符串集合实际拥有的不同非空前缀数：
```cpp
int ans{ 0 };
for (int u = 1; u < tr.size(); ++ u) {
    ans += tr.t[u].pass > 0;
}
```
##### 不同字符串数量
当前 Trie 中不同字符串的数量为：
```cpp
int distinct{ 0 };
for (int u = 0; u < tr.size(); ++ u) {
    distinct += tr.t[u].cnt > 0;
}
```
当前字符串总数则直接为：
```cpp
tr.total();
```
区别在于重复字符串只为 `distinct` 贡献一次，但会按重复次数计入 `total()`
##### 最短唯一前缀
如果每个字符串只插入一次，则字符串 `s` 的路径上第一个满足：
```cpp
tr.t[p].pass == 1
```
的节点，就是 `s` 的最短唯一前缀
```cpp
int p{ 0 };
for (int i = 0; i < s.size(); ++ i) {
    p = tr.step(p, s[i]);
    if (tr.t[p].pass == 1) {
        // s[0..i] 是最短唯一前缀
        break;
    }
}
```
若允许重复字符串，则 `pass` 按多重集合计数：
- 同一字符串出现多次时，不存在能够区分这些副本的唯一前缀
- 若题目要求区分“不同字符串”而非字符串副本，需要额外维护去重后的通过数量
##### 字典序遍历
Trie 中：
1. 当前节点对应字符串本身
2. 再依次遍历字符 `0,1,...,A-1` 的儿子
就是字符串字典序
```cpp
auto dfs = Y([&](auto self, int u) -> void {
    for (int i = 0; i < tr.t[u].cnt; ++ i) {
        // 当前前缀出现一次
    }
    for (int c = 0; c < A; ++ c) {
        int v{ tr.t[u].next[c] };
        if (!v || !tr.t[v].pass) continue;
        // 当前字符串末尾加入字符 c
        self(v);
        // 回退字符 c
    }
});
dfs(0);
```
必须先处理 `cnt[u]`，再进入儿子，因为：
```text
"a" < "aa" < "ab"
```
##### 字典序第 k 个字符串
`pass[u]` 恰好是 Trie 子树中的字符串多重集合大小
因此可以逐层跳过整个字符子树
假设 `k` 为 `1-indexed`：
```cpp
int u{ 0 };
while (true) {
    if (k <= tr.t[u].cnt) {
        // 当前前缀就是答案
        break;
    }
    k -= tr.t[u].cnt;
    for (int c = 0; c < A; ++ c) {
        int v{ tr.t[u].next[c] };
        if (!v || !tr.t[v].pass) continue;
        if (k <= tr.t[v].pass) {
            // 答案位于字符 c 的子树
            // 将 c 加入答案
            u = v;
            break;
        }
        k -= tr.t[v].pass;
    }
}
```
要求：
```cpp
1 <= k && k <= tr.total()
```
复杂度为：
$$O(LA)$$
其中 `L` 为答案长度
当 `A` 是固定小常数时通常记作 $O(L)$
重复字符串按照 `cnt[u]` 重复出现在字典序序列中
##### Trie 上树形 DP
Trie 的每个节点就是一个前缀，因此很多字符串集合问题可以直接变成树形 DP：
```cpp
auto dfs = Y([&](auto self, int u) -> void {
    for (int c = 0; c < A; ++ c) {
        int v{ tr.t[u].next[c] };
        if (!v || !tr.t[v].pass) continue;
        self(v);
        // 用 v 的 DP 信息更新 u
    }
});
```
常见建模包括：
- 选择若干字符串，使公共前缀代价最优
- 对同一前缀下的字符串分组
- Trie 子树统计
- 前缀贡献合并
- 字符串集合上的背包 / 匹配
- 按 LCP 层次进行贪心
核心对应关系是：
```text
Trie 节点     <-> 一个前缀
Trie 子树     <-> 以该前缀开头的所有字符串
祖先关系      <-> 前缀关系
LCA 深度      <-> LCP
pass[u]       <-> 当前子树中的字符串多重集合大小
cnt[u]        <-> 恰好等于当前前缀的字符串数量
```
#### 复杂度
设：
- $S$：历史创建的 Trie 节点数
- $A$：字符集大小

| 操作                                                                                                                               |      时间复杂度 |
| -------------------------------------------------------------------------------------------------------------------------------- | ---------: |
| `add(s)` / `find(s)` / `count(s)` / `contains(s)` / `prefix_count(s)` / `count_prefixes(s)` / `erase(s)` / `match_prefixes(s,f)` | $O(\|S\|)$ |
| `step(p,c)`                                                                                                                      |     $O(1)$ |
| Trie 全树遍历                                                                                                                        |    $O(SA)$ |
| 字典序第 `k` 个                                                                                                                       |    $O(LA)$ |
空间复杂度：
$$O(SA)$$
当 `A` 为固定小常数时：
- 插入 / 查询一个长度为 $n$ 的字符串：$O(n)$
- 全树遍历：$O(S)$
- 空间：$O(S)$
严格来说，每次创建新节点都需要初始化一个长度为 `A` 的 `array`，因此若不把 `A` 视为常数，插入的最坏复杂度为：
$$O(|s|A)$$
字符集很大且转移非常稀疏时，应考虑：
- 先离散化字符集
- 每节点使用稀疏边结构
而不是直接增大 `A`
