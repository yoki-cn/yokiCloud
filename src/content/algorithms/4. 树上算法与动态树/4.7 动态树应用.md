### 动态树应用
---
#### 选型
---

| 操作模型 | 推荐 |
|---|---|
| 边只增加 | `IncMST` |
| 边增加 + 权值只降低 | `IncMST::dec()` |
| 只有删边，全部操作离线 | 倒序 `IncMST` |
| 动态路径最大边 | 4.6 `LCT` |
| 删除 MST 树边后寻找替代边 | 已超出普通 LCT |
| 任意在线加边 / 删边 MST | 全动态 MST，高级专项 |
| 只要求动态连通，不要求 MST | DSU / rollback DSU / LCT / ETT 按模型选择 |
#### 增量最小生成树 / 最小生成森林
---
**解决问题：** 图中不断加入带权无向边，每次维护当前所有已加入边构成图的最小生成森林；图连通后即为 MST
核心结论：若新边 `(u,v,w)` 两端已经连通，则在当前 MST 中的 `u-v` 路径上找到最大权边 `e`
若 `w < weight(e)`，用新边替换 `e`；否则新边永久可以忽略
依赖 **4.6.1 `LCT`**，使用“边转点 + 路径最大值”
```cpp
struct IncMST {
    using P = pair<i64, int>;
    struct MaxOp {
        P operator()(const P &a, const P &b) const { return max(a, b); }
    };
    struct Edge {
        int u, v, nd{ -1 };
        i64 w;
        bool in{};
    };
    static constexpr i64 NEG{ numeric_limits<i64>::lowest() };
    int n, cc;
    i128 sum{};
    LCT<P, MaxOp> lct;
    vector<Edge> e;
    explicit IncMST(int n_) : n(n_), cc(n_), lct(vector<P>(n_, {NEG, -1}), {NEG, -1}) {}
private:
    // ===== 将边加入当前 MSF =====
    void use(int id) {
        Edge &a{ e[id] };
        if (a.nd == -1) a.nd = lct.add_node({a.w, id});
        else lct.set(a.nd, {a.w, id});
        lct.link(a.u, a.nd);
        lct.link(a.nd, a.v);
        a.in = true;
        sum += a.w;
    }
    // ===== 从当前 MSF 删除边：仅替换边时调用 =====
    void drop(int id) {
        Edge &a{ e[id] };
        lct.cut(a.u, a.nd);
        lct.cut(a.nd, a.v);
        a.in = false;
        sum -= a.w;
    }
    // ===== 尝试让一条新边 / 降权边进入 MSF =====
    void relax(int id) {
        Edge &a{ e[id] };
        if (a.u == a.v) return;
        if (!lct.conn(a.u, a.v)) {
            use(id);
            -- cc;
            return;
        }
        auto [mx, old]{ lct.query(a.u, a.v) };
        if (a.w < mx) {
            drop(old);
            use(id);
        }
    }
public:
    // ===== 基础接口 =====
    int add(int u, int v, i64 w) {
        int id{ int(e.size()) };
        e.push_back({u, v, -1, w, false});
        relax(id);
        return id;
    }
    // ===== 边权降低 =====
    bool dec(int id, i64 w) {
        Edge &a{ e[id] };
        if (a.in) {
            sum += i128(w) - a.w;
            a.w = w;
            lct.set(a.nd, {w, id});
            return true;
        }
        a.w = w;
        relax(id);
        return a.in;
    }
    bool full() const { return cc == 1; }
    bool used(int id) const { return e[id].in; }
    i64 msf() const { return sum; }
    optional<i64> mst() const {
        if (!full()) return nullopt;
        return sum;
    }
};
```
##### 接口说明
- `IncMST(n)`：初始化 `n` 个孤立节点
- `add(u,v,w)`：加入一条边，返回边编号
- `dec(id,w)`：把已有边 `id` 的权值降低到 `w`
- `used(id)`：该边当前是否位于最小生成森林中
- `full()`：当前图是否连通
- `msf()`：当前最小生成森林总权值
- `mst()`：若图已连通返回 MST 权值，否则返回 `nullopt`
- `cc`：当前图的连通块数
`dec(id,w)` 要求：
```text
0 <= id < e.size()
w <= e[id].w
```
##### 为什么只需要当前 MST
设当前最小生成树为 `T`，插入新边 `e=(u,v)`
若 `u,v` 已连通，则：
```text
T + e
```
恰好产生一个环。设环中原树最大边为 `f`：
```text
w(e) < w(f)  ->  删除 f，加入 e
w(e) >= w(f) ->  T 不需要变化
```
因此一次插边只需要查询当前树路径最大边，不需要保存所有被淘汰的非树边
这就是 LCT 特别适合增量 MST 的原因：`split(u,v)` 能把整条路径暴露成一个 Splay，从而查询路径最大边。标准 LCT 来源同样将 `split(x,y)` 定义为暴露整条 `x-y` 路径
##### 边转点
原图节点全部赋：
```cpp
{NEG, -1}
```
边：
```text
u --w-- v
```
变成：
```text
u -- edge_node -- v
```
边节点值为：
```cpp
{w, id}
```
于是：
```cpp
lct.query(u, v)
```
返回的就是路径最大边 `{权值,边编号}`
##### 常见用法
```cpp
IncMST mst(n);

for (auto [u, v, w] : edges) {
    int id{ mst.add(u, v, w) };

    if (mst.full()) {
        cout << mst.msf() << '\n';
    } else {
        cout << -1 << '\n';
    }
}
```
判断某条边当前是否在 MST：
```cpp
if (mst.used(id)) {
    // 当前生成森林边
}
```
动态降低边权：
```cpp
mst.dec(id, nw);
```
##### 注意事项
- 支持负边权
- 支持重边和自环；自环永远不会进入 MSF
- 相同权值时不主动替换旧边，仍然得到合法 MST
- 内部 `sum` 和降权差值使用 i128，避免替换时的临时森林总和或 w-old 溢出。msf()/mst() 仍返回 i64，要求每次操作完成后的 MSF 总权值在 i64 范围内；若需要更大答案，同时将这两个接口与 DelMST 的答案类型改为 i128
- 一条边最多创建一个 LCT 边节点，即使曾经进入 MST、后来被替换、再因降权重新进入，也会复用原节点
- **被插入后淘汰的边，在纯插入模型中可以永久丢弃**；这一点到了真正全动态 MST 中就不成立
##### 复杂度
设累计加入 `m` 条边：

| 操作 | 均摊复杂度 |
|---|---:|
| `add()` | $O(\log(n+m))$ |
| `dec()` | $O(\log(n+m))$ |
| `used()` / `full()` / `msf()` | $O(1)$ |
空间复杂度为 $O(n+m)$
#### 仅删边 MST 的离线倒序
如果操作只有：
```text
删除某条初始边
询问当前 MST
```
那么没必要写真正的动态删除 MST
把时间倒过来：
```text
删除边 -> 加入边
```
就重新变成了 **增量 MST**
```cpp
struct DelMST {
    struct Edge {
        int u, v;
        i64 w;
    };
    struct Op {
        int tp, id;
    };
    // tp = 0：删除边 id
    // tp = 1：询问 MST
    static vector<optional<i64>> solve(int n, const vector<Edge> &e, const vector<Op> &op) {
        vector<char> del(e.size());
        for (auto [tp, id] : op) if (tp == 0) del[id] = true;

        IncMST mst(n);
        for (int i = 0; i < int(e.size()); ++ i) {
            if (!del[i]) mst.add(e[i].u, e[i].v, e[i].w);
        }

        vector<optional<i64>> ans;
        for (int i = int(op.size()) - 1; i >= 0; -- i) {
            auto [tp, id]{ op[i] };
            if (tp == 1) {
                ans.push_back(mst.mst());
            } else {
                mst.add(e[id].u, e[id].v, e[id].w);
            }
        }
        reverse(ans.begin(), ans.end());
        return ans;
    }
};
```
##### 接口说明
`DelMST::solve(n,e,op)` 返回所有询问的答案
若某次图不连通：
```cpp
ans[i] == nullopt
```
否则：
```cpp
*ans[i]
```
即 MST 权值
##### 注意事项
要求：
```text
所有边最开始存在
每条边最多删除一次
不存在重新加入操作
```
如果操作同时有：
```text
add
delete
```
倒序后仍然同时存在：
```text
delete
add
```
就不能靠这一招解决
##### 常见用法
```cpp
auto ans{ DelMST::solve(n, edges, ops) };

for (auto x : ans) {
    if (x) cout << *x << '\n';
    else cout << -1 << '\n';
}
```
##### 复杂度
每条原边恰好被加入 `IncMST` 一次，因此总复杂度：
$$
O(m\log(n+m)+q)
$$
空间复杂度：
$$
O(n+m+q)
$$
#### 动态 MST 的能力边界
---
这一部分非常重要。**LCT 能维护动态树，不代表“LCT = 全动态 MST”**
当前 `IncMST` 真正容易支持的操作如下：

| 图操作 | 是否容易支持 | 原因 |
|---|---:|---|
| 插入边 | ✅ | 环上删除最大边 |
| 非树边降权 | ✅ | 重新尝试环替换 |
| 树边降权 | ✅ | 当前 MST 仍然最优 |
| 删除非树边 | 当前 MST 不变 | 但全动态场景不能永久忘掉它 |
| 非树边升权 | 当前 MST 不变 | 不影响当前树 |
| 删除树边 | ❌ | 需要寻找割两侧最小替代边 |
| 树边升权 | ❌ | 可能需要寻找替代边 |
| 任意插入 + 删除 | ❌ | 必须维护非树边候选关系 |
##### 真正困难的地方
假设 MST 中删除了树边：
```text
u ----- v
```
森林被切成两个连通块：
```text
A | B
```
此时必须在**所有非树边**中寻找：
```text
连接 A 与 B 的最小权边
```
而普通 LCT 擅长的是：
```text
给定 u,v
查询树上 u-v 路径
```
它并不能直接回答：
```text
当前两个连通块之间有哪些非树边？
其中最小的是谁？
```
所以：
```text
路径最大边
```
和：
```text
割上的最小替代边
```
是两个完全不同的问题
##### 为什么增量 MST 可以丢弃非树边
纯插入时，一条边在加入那一刻如果不能改善当前 MST，那么它以后也不需要重新考虑
但是允许删树边以后：
```text
曾经没进入 MST 的边
```
可能突然成为最佳替代边
因此全动态 MST 必须保留并组织大量非树边，这也是复杂度陡增的根源
##### ETT 能不能直接解决
不能
4.6 的 ETT 可以很好地维护：
```text
link / cut
连通块大小
连通块聚合信息
```
但它同样没有自动维护：
```text
两个连通块之间最小的非树边
```
所以：
```text
ETT + 最小生成树
```
仍然需要额外的 replacement-edge 结构
##### Top Tree 能不能直接解决
也不能“自动解决”
Top Tree 比 LCT 更擅长维护复杂树 DP 和 Cluster 信息，但**全动态 MST 的非树边管理依然是额外问题**
##### 真正的全动态 MST
理论上的全动态 MST 通常需要维护多层动态森林以及不同层级的非树边，并在树边删除后高效寻找替代边。实现复杂度远高于普通 LCT，不适合把几百行实现作为常规赛场板子
竞赛中更应该先根据操作限制降级问题：
```text
只有插边
-> IncMST

插边 + 降权
-> IncMST

只有删边且离线
-> 倒序 IncMST

静态图，只询问删某一条 MST 边后的结果
-> MST + 非树边替换预处理

任意 add / delete，但数据较小
-> 分块 / 周期重构

任意 add / delete，且必须在线
-> 真正 fully dynamic MST
```
##### 一个常见误区
下面这种东西：
```text
时间线段树 + rollback DSU
```
非常适合解决**离线动态连通性**，但它不能直接维护动态 MST 权值。
因为 DSU 只能回答：
```text
两个点是否已经连通
```
而 Kruskal 还依赖边的**全局权值顺序**。一条边在某个时间区间有效，并不能简单地按时间线段树 DFS 顺序执行 Kruskal
动态 MST 的离线算法通常还需要额外的**边收缩、边删除 / 归约、分治**等技巧，明显比动态连通复杂。
#### 常见对称扩展
---
##### 增量最大生成树
与 `IncMST` 完全对称
最小生成树是：
```text
新边形成环
删除环上最大边
```
最大生成树改为：
```text
新边形成环
删除环上最小边
```
因此只需要让 LCT 路径维护：
```text
最小边
```
并把判断：
```cpp
if (a.w < mx)
```
改成：
```cpp
if (a.w > mn)
```
同时应将 MaxOp 换为 MinOp，并把原节点和单位元设为 {numeric_limits<i64>::max(), 哨兵编号}；按 pair 的比较顺序选择不会抢占真实边的编号。不能只翻转上述不等号。
