### 动态树
---
#### 选型
---

| 需求 | 推荐 |
|---|---|
| 动态 `link / cut / connected` | `LCT` |
| 动态路径和 / 最大值 / 异或 | `LCT` |
| 非交换路径信息 | `LCT` 双向聚合 |
| 路径第 $k$ 点 | `LCT::kth()` |
| 动态边权 | LCT 边转点 |
| 动态 MST 中查询路径最大边 | LCT 边转点 + `MaxOp` |
| 动态整棵连通分量大小 / 和 | `ETT` |
| 动态子树 / 分量类问题 | 优先考虑 ETT |
| 非常复杂的动态树 DP | Top Tree |
#### Link-Cut Tree
---
**解决问题：** 动态维护森林，支持连边、删边、连通性以及树上路径信息查询；可通过边转点维护边权
`Op` 只要求满足结合律，`id` 为单位元。内部额外维护正反两个聚合值，因此也支持矩阵乘法、字符串拼接等**非交换路径信息**
```cpp
template<class T, class Op = plus<T>>
struct LCT {
    struct Node {
        int ch[2]{}, fa{}, siz{ 1 };
        bool rev{};
        T val{}, sum[2]{};
    };
    int n;
    T id;
    Op op;
    vector<Node> tr;
    vector<int> stk;
    explicit LCT(int n_, T id_ = T{}, Op op_ = Op())
        : n(n_), id(id_), op(op_), tr(n + 1) {
        tr[0].siz = 0;
        tr[0].sum[0] = tr[0].sum[1] = id;
        stk.reserve(n + 1);
        for (int x = 1; x <= n; ++ x) tr[x].sum[0] = tr[x].sum[1] = tr[x].val;
    }
    LCT(const vector<T> &a, T id_ = T{}, Op op_ = Op())
        : LCT(int(a.size()), id_, op_) {
        for (int u = 0; u < n; ++ u) {
            int x{ u + 1 };
            tr[x].val = tr[x].sum[0] = tr[x].sum[1] = a[u];
        }
    }
private:
    // ===== Splay 基础维护 =====
    bool root(int x) const {
        int f{ tr[x].fa };
        return !f || (tr[f].ch[0] != x && tr[f].ch[1] != x);
    }
    void pull(int x) {
        auto &u{ tr[x] };
        int l{ u.ch[0] }, r{ u.ch[1] };
        u.siz = tr[l].siz + 1 + tr[r].siz;
        u.sum[0] = op(op(tr[l].sum[0], u.val), tr[r].sum[0]);
        u.sum[1] = op(op(tr[r].sum[1], u.val), tr[l].sum[1]);
    }
    void apply_rev(int x) {
        if (!x) return;
        swap(tr[x].ch[0], tr[x].ch[1]);
        swap(tr[x].sum[0], tr[x].sum[1]);
        tr[x].rev ^= 1;
    }
    void push(int x) {
        if (!tr[x].rev) return;
        apply_rev(tr[x].ch[0]);
        apply_rev(tr[x].ch[1]);
        tr[x].rev = false;
    }
    void rotate(int x) {
        int y{ tr[x].fa }, z{ tr[y].fa };
        int k{ tr[y].ch[1] == x }, w{ tr[x].ch[k ^ 1] };
        if (!root(y)) tr[z].ch[tr[z].ch[1] == y] = x;
        tr[x].fa = z;
        tr[y].ch[k] = w;
        if (w) tr[w].fa = y;
        tr[x].ch[k ^ 1] = y;
        tr[y].fa = x;
        pull(y);
        pull(x);
    }
    void splay(int x) {
        stk.clear();
        stk.push_back(x);
        for (int y{ x }; !root(y); y = tr[y].fa) stk.push_back(tr[y].fa);
        while (!stk.empty()) {
            push(stk.back());
            stk.pop_back();
        }
        while (!root(x)) {
            int y{ tr[x].fa }, z{ tr[y].fa };
            if (!root(y)) rotate((tr[y].ch[1] == x) == (tr[z].ch[1] == y) ? y : x);
            rotate(x);
        }
        pull(x);
    }
    // ===== 实链操作：link / cut / query 等均依赖，不建议删除 =====
    int access(int x) {
        int y{};
        for (int z{ x }; z; z = tr[z].fa) {
            splay(z);
            tr[z].ch[1] = y;
            pull(z);
            y = z;
        }
        splay(x);
        return y;
    }
    void mkrt(int x) {
        access(x);
        apply_rev(x);
    }
    int froot(int x) {
        access(x);
        while (true) {
            push(x);
            if (!tr[x].ch[0]) break;
            x = tr[x].ch[0];
        }
        splay(x);
        return x;
    }
    void split(int x, int y) {
        mkrt(x);
        access(y);
    }

public:
    // ===== 节点与森林基础操作 =====
    int add_node(const T &v = T{}) {
        ++ n;
        tr.push_back(Node());
        int x{ n };
        tr[x].val = tr[x].sum[0] = tr[x].sum[1] = v;
        return n - 1;
    }
    void set(int u, const T &v) {
        int x{ u + 1 };
        access(x);
        tr[x].val = v;
        pull(x);
    }
    bool conn(int u, int v) {
        int x{ u + 1 }, y{ v + 1 };
        if (x == y) return true;
        mkrt(x);
        return froot(y) == x;
    }
    bool link(int u, int v) {
        int x{ u + 1 }, y{ v + 1 };
        mkrt(x);
        if (froot(y) == x) return false;
        tr[x].fa = y;
        return true;
    }
    bool cut(int u, int v) {
        int x{ u + 1 }, y{ v + 1 };
        mkrt(x);
        access(y);
        if (tr[y].ch[0] != x || tr[x].ch[1]) return false;
        tr[y].ch[0] = tr[x].fa = 0;
        pull(y);
        return true;
    }

    // ===== 路径信息 =====
    T query(int u, int v) {
        int x{ u + 1 }, y{ v + 1 };
        split(x, y);
        return tr[y].sum[0];
    }
    int plen(int u, int v) {
        int x{ u + 1 }, y{ v + 1 };
        split(x, y);
        return tr[y].siz;
    }
    int kth(int u, int v, int k) {
        int x{ u + 1 }, y{ v + 1 };
        split(x, y);
        if (k < 0 || k >= tr[y].siz) return -1;
        int z{ y };
        while (true) {
            push(z);
            int l{ tr[z].ch[0] }, s{ tr[l].siz };
            if (k < s) z = l;
            else if (k == s) break;
            else k -= s + 1, z = tr[z].ch[1];
        }
        splay(z);
        return z - 1;
    }
};
```
##### 模板参数
- `T`：单点值以及路径聚合值类型
- `Op`：结合运算
- `id`：`Op` 的单位元
例如求和：
```cpp
LCT<i64> lct(a, 0);
```
路径异或：
```cpp
struct Xor {
    i64 operator()(i64 a, i64 b) const { return a ^ b; }
};
LCT<i64, Xor> lct(a, 0);
```
##### 接口
- `LCT(a,id,op)`：建立 `n=a.size()` 个互不相连的节点
- `add_node(v)`：新建值为 `v` 的节点，返回其 `0base` 编号
- `set(u,v)`：修改节点值
- `conn(u,v)`：判断是否连通
- `link(u,v)`：若不连通则加入边，成功返回 `true`
- `cut(u,v)`：若 `(u,v)` 是现有边则删除，成功返回 `true`
- `query(u,v)`：返回路径 `u -> v` 的聚合值
- `plen(u,v)`：路径节点数
- `kth(u,v,k)`：路径 `u -> v` 上第 `k` 个节点，`k=0` 为 `u`
标准 LCT 中 `access()` 暴露根到当前节点的实链，`makeroot()` 通过翻转路径改变表示根，随后 `split(x,y)` 即可让整条 `x-y` 路径落入一个 Splay
##### 注意事项
- 对外节点编号是 `0..n-1`；内部使用 `1..n`，`0` 为哨兵
- `query()`、`plen()`、`kth()` 要求 `u,v` 已连通
- `link()` 会阻止成环；LCT 维护的是**森林**，不是一般动态图
- `cut(u,v)` 只删除真实存在的直接边，不能传路径上两个不相邻节点
- 所有操作都会改变 preferred path，因此不要把某个 Splay 的形态当成原树结构
- `sum[0]` 表示当前辅助树左到右的信息，`sum[1]` 表示右到左；翻转时交换两者，所以 `Op` **不要求交换律**
- `Op` 必须满足结合律；若使用非默认单位元，构造时必须传入正确的 `id`
- 单次 Splay 操作最坏可能达到线性，但 LCT 操作的**均摊复杂度**为 $O(\log n)$
Splay 中需要正确下传翻转标记后才能旋转
##### 常见用法
###### 动态森林路径和
```cpp
LCT<i64> lct(a, 0);

lct.link(u, v);
i64 ans{ lct.query(u, v) };
lct.set(u, x);
lct.cut(u, v);
```
###### 非交换路径信息
例如 `Op(a,b)` 表示矩阵乘法，则：
```cpp
auto x{ lct.query(u, v) };
```
得到的是严格按照 `u -> v` 顺序的乘积，而：
```cpp
auto y{ lct.query(v, u) };
```
顺序相反
##### 复杂度
| 操作 | 均摊复杂度 |
|---|---:|
| `set()` | $O(\log n)$ |
| `conn()` | $O(\log n)$ |
| `link()` / `cut()` | $O(\log n)$ |
| `query()` / `plen()` / `kth()` | $O(\log n)$ |
空间复杂度：$O(n)$
#### LCT 常见扩展
---
##### 边权转点权
LCT 天然维护节点，因此动态边权最稳妥的写法是：**每条边新建一个边节点**
原边：
```text
u --w-- v
```
改成：
```text
u -- e -- v
```
其中 `e` 的节点值为边权
例如维护路径最大边：
```cpp
using P = pair<i64, int>;

struct MaxOp {
    P operator()(const P &a, const P &b) const { return max(a, b); }
};

constexpr i64 NEG{ numeric_limits<i64>::lowest() };
LCT<P, MaxOp> lct(vector<P>(n, {NEG, -1}), {NEG, -1});

int e{ lct.add_node({w, id}) };
lct.link(u, e);
lct.link(e, v);
```
查询：
```cpp
auto [mx, id]{ lct.query(u, v) };
```
删除该边：
```cpp
lct.cut(u, e);
lct.cut(e, v);
```
这也是后面**增量 MST / 动态 MST**最值得直接复用的写法
##### 路径加 + 路径和
不建议默认把懒标记塞进核心 LCT，否则普通动态连通 / 动态 MST 时会白抄一坨代码
若确实需要数值路径加，在前面的求和版上做以下扩展即可
`Node` 增加：
```cpp
T add{};
```
增加：
```cpp
void apply_add(int x, const T &v) {
    if (!x) return;
    tr[x].val += v;
    tr[x].sum[0] += v * tr[x].siz;
    tr[x].sum[1] += v * tr[x].siz;
    tr[x].add += v;
}
```
把 `push()` 改为：
```cpp
void push(int x) {
    if (tr[x].rev) {
        apply_rev(tr[x].ch[0]);
        apply_rev(tr[x].ch[1]);
        tr[x].rev = false;
    }
    if (tr[x].add != T{}) {
        apply_add(tr[x].ch[0], tr[x].add);
        apply_add(tr[x].ch[1], tr[x].add);
        tr[x].add = T{};
    }
}
```
再加入：
```cpp
void add_path(int u, int v, const T &x) {
    int a{ u + 1 }, b{ v + 1 };
    split(a, b);
    apply_add(b, x);
}
```
此扩展只适用于：
```text
Op = plus<T>
```
并要求 `T` 支持加法以及乘以路径长度
##### 路径赋值 / 仿射修改
结构不变，本质仍然是：
```cpp
split(u, v);
apply(root, tag);
```
区别仅在于 `Tag` 的复合以及它如何作用于 `val / sum`。如果既有赋值又有加法，应保证标记复合顺序与线段树中完全一致
##### 路径第 k 点
核心版已经实现：
```cpp
lct.kth(u, v, k);
```
因此不需要再准备单独的倍增结构
##### 子树信息
普通 LCT 的辅助树只天然维护**实链路径**，不能直接把：
```cpp
tr[x].sum
```
当成原树子树信息。
若一定要维护动态子树和，需要在 `access()` 中维护虚儿子贡献，例如：
```text
all[x] = 左右实儿子贡献 + 自身 + virtual[x]
```
并在实边 / 虚边切换时增减 `virtual[x]`。这个版本与具体 `Info`、可逆性、根定义关系很强，不建议塞进通用核心；只需要动态连通分量统计时，下面的 ETT 更自然
#### Euler Tour Tree
---
**解决问题：** 动态森林中的连通性、连边、删边以及**整棵连通分量信息**。它把一棵树的 Euler Tour 存进隐式 Treap
相比 LCT：
- LCT 更擅长**路径**
- ETT 更擅长**整个连通分量 / 根树子树类信息**
下面维护：
```text
动态连通
连边 / 按边编号删边
连通分量节点数
连通分量点权和
单点修改
```

```cpp
struct ETT {
    struct Node {
        int ch[2]{}, fa{}, siz{ 1 }, cnt{}, own{};
        u64 pri{};
        i64 val{}, sum{};
    };
    struct Edge {
        int a{}, b{};
        bool on{};
    };
    vector<Node> tr{{}};
    vector<int> self, free;
    vector<Edge> e;

    explicit ETT(int n) : self(n) {
        tr.reserve(n + 1);
        for (int u = 0; u < n; ++ u) self[u] = node(1);
    }
    explicit ETT(const vector<i64> &a) : self(a.size()) {
        tr.reserve(a.size() + 1);
        for (int u = 0; u < int(a.size()); ++ u) self[u] = node(1, a[u]);
    }
private:
    // ===== 隐式 Treap =====
    static u64 rnd(u64 x) {
        x += 0x9e3779b97f4a7c15ULL;
        x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9ULL;
        x = (x ^ (x >> 27)) * 0x94d049bb133111ebULL;
        return x ^ (x >> 31);
    }
    int node(int own = 0, i64 val = 0) {
        int x;
        if (free.empty()) x = tr.size(), tr.push_back(Node());
        else x = free.back(), free.pop_back(), tr[x] = Node();
        tr[x].own = tr[x].cnt = own;
        tr[x].val = tr[x].sum = val;
        tr[x].pri = rnd(x);
        return x;
    }
    int sz(int x) const { return x ? tr[x].siz : 0; }
    int cnt(int x) const { return x ? tr[x].cnt : 0; }
    i64 sum(int x) const { return x ? tr[x].sum : 0; }
    void pull(int x) {
        tr[x].siz = sz(tr[x].ch[0]) + 1 + sz(tr[x].ch[1]);
        tr[x].cnt = cnt(tr[x].ch[0]) + tr[x].own + cnt(tr[x].ch[1]);
        tr[x].sum = sum(tr[x].ch[0]) + tr[x].val + sum(tr[x].ch[1]);
        for (int k = 0; k < 2; ++ k) if (tr[x].ch[k]) tr[tr[x].ch[k]].fa = x;
    }
    int merge(int a, int b) {
        if (!a || !b) {
            int x{ a ? a : b };
            if (x) tr[x].fa = 0;
            return x;
        }
        if (tr[a].pri < tr[b].pri) {
            tr[a].ch[1] = merge(tr[a].ch[1], b);
            pull(a);
            tr[a].fa = 0;
            return a;
        }
        tr[b].ch[0] = merge(a, tr[b].ch[0]);
        pull(b);
        tr[b].fa = 0;
        return b;
    }
    pair<int, int> split(int x, int k) {
        if (!x) return {};
        if (sz(tr[x].ch[0]) >= k) {
            auto [a, b]{ split(tr[x].ch[0], k) };
            tr[x].ch[0] = b;
            pull(x);
            tr[x].fa = 0;
            if (a) tr[a].fa = 0;
            return {a, x};
        }
        auto [a, b]{ split(tr[x].ch[1], k - sz(tr[x].ch[0]) - 1) };
        tr[x].ch[1] = a;
        pull(x);
        tr[x].fa = 0;
        if (b) tr[b].fa = 0;
        return {x, b};
    }
    // ===== Euler Tour 定位与循环移位 =====
    int root(int x) const {
        while (tr[x].fa) x = tr[x].fa;
        return x;
    }
    int pos(int x) const {
        int res{ sz(tr[x].ch[0]) };
        while (tr[x].fa) {
            int p{ tr[x].fa };
            if (tr[p].ch[1] == x) res += sz(tr[p].ch[0]) + 1;
            x = p;
        }
        return res;
    }
    int reroot(int x) {
        int r{ root(x) }, k{ pos(x) };
        auto [a, b]{ split(r, k) };
        return merge(b, a);
    }
    void pull_up(int x) {
        while (x) {
            pull(x);
            x = tr[x].fa;
        }
    }

public:
    // ===== 动态森林接口 =====
    bool conn(int u, int v) const { return root(self[u]) == root(self[v]); }
    int size(int u) const { return cnt(root(self[u])); }
    i64 query(int u) const { return sum(root(self[u])); }
    void set(int u, i64 v) {
        int x{ self[u] };
        tr[x].val = v;
        pull_up(x);
    }
    int link(int u, int v) {
        if (conn(u, v)) return -1;
        int x{ reroot(self[u]) }, y{ reroot(self[v]) };
        int a{ node() }, b{ node() }, id{ int(e.size()) };
        e.push_back({a, b, true});
        merge(merge(merge(x, a), y), b);
        return id;
    }
    bool cut(int id) {
        if (id < 0 || id >= int(e.size()) || !e[id].on) return false;
        int a{ e[id].a }, b{ e[id].b };
        int r{ reroot(a) };
        auto [x, s]{ split(r, 1) };
        int k{ pos(b) };
        auto [l, y]{ split(s, k) };
        auto [z, rr]{ split(y, 1) };
        (void)x;
        (void)l;
        (void)z;
        (void)rr;
        tr[a].ch[0] = tr[a].ch[1] = tr[a].fa = 0;
        tr[b].ch[0] = tr[b].ch[1] = tr[b].fa = 0;
        e[id].on = false;
        free.push_back(a);
        free.push_back(b);
        return true;
    }
};
```
##### 原理
每个真实节点有一个唯一的：
```text
self[u]
```
节点；每条树边 `(u,v)` 在 Euler Tour 中加入两个有向出现：
```text
u -> v
v -> u
```
因此一棵树对应一个循环 Euler Tour
连接两棵树时：
```text
Tour(u) + (u,v) + Tour(v) + (v,u)
```
删除边时，删掉这两个有向出现，循环序列自然被切成两棵树
`own=1` 只出现在真实节点的 `self[u]` 上，因此：
```cpp
size(u)
```
不会把边的两个 Euler Tour 节点计入
##### 接口说明
- `ETT(n)`：建立 `n` 个孤立点，初始点权为 `0`
- `ETT(a)`：建立 `n=a.size()` 个孤立点
- `conn(u,v)`：是否位于同一棵树
- `link(u,v)`：若不连通则连接，返回**边编号**；失败返回 `-1`
- `cut(id)`：删除 `link()` 返回的边编号
- `set(u,x)`：修改点权
- `size(u)`：`u` 所在连通分量节点数
- `query(u)`：`u` 所在连通分量点权和
##### 常见用法
```cpp
ETT ett(a);

int id{ ett.link(u, v) };
cout << ett.size(u) << '\n';
cout << ett.query(u) << '\n';

ett.set(u, x);
ett.cut(id);
```
##### 注意事项
- 必须保存 `link()` 返回的边编号，当前板子按编号删边
- ETT 同样只维护森林，不能 `link()` 两个已连通节点
- 一条边使用两个 Treap 节点
- 删除边后两个 Treap 节点进入空闲表，后续 link 复用；活跃森林最多 n-1 条边，节点池为 O(n)。边编号不复用，历史 Edge 记录仍为 O(q)，旧编号重复 cut 返回 false
- Treap 使用 SplitMix 生成固定伪随机优先级，表中期望复杂度采用随机优先级模型；固定公开序列对针对性构造不提供最坏对数保证
- 当前版本维护的是**整个连通分量的点数与点权和**；若需要其他满足结合律的分量信息，可以修改 `Node::sum / pull()`
- 如果题目核心是 `u-v` 路径最大值、路径和等，LCT 明显更直接，不要为了 ETT 而 ETT
##### 复杂度
设累计创建的 Treap 节点数为 $N$：

| 操作 | 期望复杂度 |
|---|---:|
| `conn()` | $O(\log N)$ |
| `link()` / `cut()` | $O(\log N)$ |
| `set()` | $O(\log N)$ |
| `size()` / `query()` | $O(\log N)$ |
空间复杂度：$O(n+q)$
#### Top Tree
---
Top Tree 将树拆成若干 **Cluster**。每个 Cluster 至多有两个边界点，通过不断合并 Cluster 维护整棵动态树
主要合并形态可以理解为：
```text
Compress：两段路径首尾连接
Rake：把旁支子树挂到主路径
```
它能够同时覆盖很多 LCT 不自然的问题，例如动态维护：
```text
树直径
全局 DP
与根无关的子树信息
路径 + 旁支信息
更复杂的动态树 DP
```
##### 与 LCT / ETT 的区别
| 数据结构 | 最自然的维护对象 | `link/cut` | 路径信息 | 分量/子树信息 | 实现难度 |
|---|---|---:|---:|---:|---:|
| LCT | preferred path | $O(\log n)$ 均摊 | 很强 | 较麻烦 | 中高 |
| ETT | Euler Tour 序列 | $O(\log n)$ 期望 | 较弱 | 很强 | 高 |
| Top Tree | Cluster | $O(\log n)$ | 很强 | 很强 | 很高 |
赛场上建议按下面的优先级判断：
```text
动态路径问题
    -> LCT

动态连通 + 整个分量统计
    -> ETT

动态树 DP / 动态直径等 LCT 很难自然维护的问题
    -> 再考虑 Top Tree
```
对于绝大多数 ICPC / OI 题，**LCT + 边转点**已经覆盖真正需要现场模板支持的动态树问题。Top Tree 更适合作为“知道它能干什么”的能力索引，而不是打印模板的一部分
