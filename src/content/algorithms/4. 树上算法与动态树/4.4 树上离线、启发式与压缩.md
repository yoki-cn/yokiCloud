### 4.4 树上离线、启发式与压缩
---
#### 选型

| 问题形态 | 优先选择 |
|---|---|
| 求每个节点的子树统计，单点可增删 | **DSU on Tree** |
| 每个子树天然维护一个可合并容器 | **Small-to-Large** |
| 每次只关心少量关键点 | **虚树** |
| 大量离线路径统计，单点可增删 | **树上莫队** |
| 路径统计满足结合律，可在线区间维护 | 优先 **HLD + 数据结构** |
#### DSU on Tree
---
**解决问题：** 离线计算每个节点子树的信息，要求单个节点能够快速加入 / 删除当前状态，例如子树颜色种数、众数、频次统计等
核心顺序是：轻儿子先算完并清空，重儿子计算后保留，再把所有轻子树重新加入，得到当前整个子树的信息
依赖 **4.1.1 `TreeInfo`**
```cpp
struct DSUTree {
    const TreeInfo &t;
    vector<int> son;
    explicit DSUTree(const TreeInfo &t_) : t(t_), son(t.n, -1) {
        for (int u = 0; u < t.n; ++ u) {
            for (auto [v, w] : t.g[u]) {
                if (t.fa[v] != u) continue;
                if (son[u] == -1 || t.siz[v] > t.siz[son[u]]) son[u] = v;
            }
        }
    }
    template<class Add, class Del, class Calc>
    void run(Add add, Del del, Calc calc) const {
        auto sub = [&](int u, auto &&f) {
            for (int i = t.in[u]; i < t.out[u]; ++ i) f(t.seq[i]);
        };
        struct F { int u; bool keep, end; };
        vector<F> stk{{t.root, false, false}};
        while (!stk.empty()) {
            auto [u, keep, end]{ stk.back() };
            stk.pop_back();
            if (!end) {
                stk.push_back({u, keep, true});
                if (son[u] != -1) stk.push_back({son[u], true, false});
                for (auto [v, w] : t.g[u]) {
                    if (t.fa[v] == u && v != son[u]) stk.push_back({v, false, false});
                }
                continue;
            }
            for (auto [v, w] : t.g[u]) {
                if (t.fa[v] == u && v != son[u]) sub(v, add);
            }
            add(u);
            calc(u);
            if (!keep) sub(u, del);
        }
    }
};
```
##### 成员变量
- `son[u]`：`u` 的重儿子，即子树大小最大的儿子，不存在为 `-1`
##### 接口
- `DSUTree(t)`：预处理重儿子，$O(n)$
- `run(add,del,calc)`：依次求所有节点的子树答案
  - `add(u)`：将节点 `u` 加入当前状态
  - `del(u)`：将节点 `u` 从当前状态删除
  - `calc(u)`：当前状态恰好为 `u` 的整棵子树时调用
##### 注意事项
- 构造前必须完成 `TreeInfo::build()`
- `add()` 和 `del()` 必须互为逆操作
- `calc(u)` 只能读取当前状态，不应破坏全局统计
- `run()` 结束后会把根子树也清空，因此外部状态恢复为空
- `sub()` 利用 `TreeInfo` 的 `[in[u],out[u])` 枚举整棵子树
- 使用显式事件栈，轻儿子清空、重儿子保留的顺序不变；链状树不会消耗 O(n) 层 C++ 调用栈
- DSU on Tree 的“重儿子”按**子树大小**定义，与 4.3.2 长链剖分的长儿子不同
##### 常见用法
###### 每个子树有多少种颜色
```cpp
vector<int> cnt(m), ans(n);
int cur{};

auto add = [&](int u) {
    if (cnt[col[u]] ++ == 0) ++ cur;
};
auto del = [&](int u) {
    if (-- cnt[col[u]] == 0) -- cur;
};
auto calc = [&](int u) {
    ans[u] = cur;
};

DSUTree dsu(tr);
dsu.run(add, del, calc);
```
复杂状态也只需要修改三个回调
##### 复杂度
若一次 `add/del` 为 $O(T)$：

| 操作 | 复杂度 |
|---|---:|
| 构造 | $O(n)$ |
| `add/del` 调用总次数 | $O(n\log n)$ |
| `run()` | $O(n\log n\cdot T)$ |
额外空间复杂度：$O(n)$，不计用户维护的状态
#### Small-to-Large / 树上小并大
---
**解决问题：** 每棵子树维护一个可以合并的容器，将较小状态合入较大状态，使每个元素只被搬运少量次数
核心原则就是始终把“小容器”合并到“大容器”
下面给最常用的 **子树 `map` 频次合并骨架**
```cpp
template<class K>
struct SmallMerge {
    const TreeInfo &t;
    vector<map<K, int>> f;
    vector<int> num;
    explicit SmallMerge(const TreeInfo &t_) : t(t_), f(t.n), num(t.n) {}
    void merge(int u, int v) {
        if (num[u] < num[v]) {
            swap(f[u], f[v]);
            swap(num[u], num[v]);
        }
        for (auto &[x, c] : f[v]) f[u][x] += c;
        num[u] += num[v];
        num[v] = 0;
        f[v].clear();
    }
    template<class F>
    void run(const vector<K> &a, F calc) {
        for (auto &mp : f) mp.clear();
        fill(num.begin(), num.end(), 0);
        for (int i = t.n - 1; i >= 0; -- i) {
            int u{ t.seq[i] };
            ++ f[u][a[u]];
            ++ num[u];
            calc(u, f[u]);
            if (u != t.root) merge(t.fa[u], u);
        }
    }
};
```
##### 接口说明
- `f[u]`：当前归属于 `u` 的频次表
- `num[u]`：当前容器实际代表的原树节点数
- `merge(u,v)`：将 `v` 的状态合并进 `u`，小并大
- `run(a,calc)`：
  - 节点 `u` 自身贡献键 `a[u]`
  - 当 `calc(u,f[u])` 被调用时，`f[u]` 正好表示整个 `u` 子树
  - 随后 `f[u]` 会被合并进父节点
##### 注意事项
- `calc()` 必须在回调中立刻保存答案；之后 `f[u]` 可能被交换并清空
- 本板子默认一个节点贡献一个键 `a[u]`；如果一个节点贡献多个元素，修改加入自身信息的部分即可
- `num` 按实际代表的节点数比较大小，而不是直接使用 `map::size()`；有重复键时这样更稳妥
- `map` 是确定性版本；如果数据很大且已有安全哈希表，可以换成 `unordered_map` / `FlatHashMap`
- DSU on Tree 使用**一个全局状态反复增删**；Small-to-Large 使用**每棵子树自己的容器并不断合并**，两者不要混为一个板子
##### 常见用法
###### 每棵子树颜色出现次数
```cpp
SmallMerge<int> sm(tr);
vector<int> ans(n);

sm.run(col, [&](int u, const auto &mp) {
    ans[u] = mp.size();
});
```
若要求某种更复杂统计，直接根据 `mp` 维护附加信息通常比每次重新遍历整个 `map` 更好
##### 复杂度
当前使用 `map`：
- 每个节点代表的信息只会由较小集合向较大集合移动 $O(\log n)$ 次
- 单次 `map` 插入 / 修改为 $O(\log n)$
因此总时间复杂度为 $O(n\log^2 n)$，空间复杂度为 $O(n)$
若换成均摊 $O(1)$ 的哈希容器，典型总复杂度可降为均摊 $O(n\log n)$
#### 虚树
---
**解决问题：** 一次询问只关心原树中的 $k$ 个关键点时，只保留关键点及必要 LCA，把原树压缩成 $O(k)$ 个节点的树，再在虚树上 DP
经典构造就是：按 DFS 序排序关键点，加入相邻点 LCA，再排序去重并建立父子关系
依赖任意具有 `lca(u,v)` 和成员 `t` 的 LCA 结构，例如 **4.2 `LCA` / `ELCA`** 或 **4.3 `HLD`**
```cpp
template<class L>
struct VTree {
    const L &l;
    vector<vector<int>> g;
    vector<int> ver;
    explicit VTree(const L &l_) : l(l_), g(l.t.n) {}
    int build(vector<int> a) {
        for (int u : ver) g[u].clear();
        ver.clear();
        if (a.empty()) return -1;
        auto cmp = [&](int u, int v) {
            return l.t.in[u] < l.t.in[v];
        };
        sort(a.begin(), a.end(), cmp);
        a.erase(unique(a.begin(), a.end()), a.end());
        int m{ int(a.size()) };
        for (int i = 1; i < m; ++ i) a.push_back(l.lca(a[i - 1], a[i]));
        sort(a.begin(), a.end(), cmp);
        a.erase(unique(a.begin(), a.end()), a.end());
        ver = a;
        vector<int> stk{ a[0] };
        for (int i = 1; i < int(a.size()); ++ i) {
            while (!l.t.is_anc(stk.back(), a[i])) stk.pop_back();
            g[stk.back()].push_back(a[i]);
            stk.push_back(a[i]);
        }
        return a[0];
    }
};
```
##### 成员变量
- `g[u]`：虚树中 `u` 的儿子
- `ver`：本次虚树包含的全部节点，按原树 DFS 序排列
##### 接口
- `VTree(l)`：绑定 LCA 结构，$O(n)$ 初始化空邻接表
- `build(a)`：以 `a` 中节点为关键点建立虚树，返回虚树根
  - `a` 为空时返回 `-1`
  - 自动去除重复关键点
  - 自动补入必要 LCA
##### 注意事项
- `g` 是**从虚树父亲指向儿子**的有向邻接表
- 虚树节点包括原关键点与补入的 LCA；若需要区分关键点，应在外部自己维护标记数组
- 若必须让原树根出现在虚树中，直接把 `t.root` 加入关键点
- 每次 `build()` 会自动清空上一棵虚树用过的节点，不需要 $O(n)$ 清空整张 `g`
- 对一条虚边 `u -> v`：
  - 原树边数为 `l.t.dep[v] - l.t.dep[u]`
  - 原树路径权值和为 `l.t.dis[v] - l.t.dis[u]`
- 因为 `ver` 中祖先一定早于后代，所以反向遍历 `ver` 可以直接做自底向上的虚树 DP
##### 常见用法
```cpp
LCA lca(tr);
VTree vt(lca);

int root{ vt.build(key) };

for (int i = int(vt.ver.size()) - 1; i > 0; -- i) {
    int u{ vt.ver[i] };
    // 处理 u，再向虚树父节点合并
}
```
直接遍历虚树：
```cpp
auto dfs = [&](auto &&self, int u) -> void {
    for (int v : vt.g[u]) {
        i64 w{ tr.dis[v] - tr.dis[u] };
        self(self, v);
    }
};
if (root != -1) dfs(dfs, root);
```
##### 复杂度
设关键点数为 $k$，最终虚树节点数不超过 $2k-1$
使用倍增 `LCA`：
$$
O(k\log k+k\log n)
$$
使用 $O(1)$ 查询的 `ELCA`：
$$
O(k\log k)
$$
单次虚树空间为 $O(k)$；对象的邻接表本身为 $O(n)$
#### 树上莫队
---
**解决问题：** 大量离线树上路径询问，且答案能够通过单个节点的加入 / 删除快速维护
树上莫队的核心是每个节点在 DFS 时记录**进入和离开各一次**，再结合 LCA 把树路径转换为欧拉序区间，之后运行普通莫队
依赖任意具有 `lca(u,v)` 和成员 `t` 的 LCA 结构
```cpp
template<class L>
struct TreeMo {
    struct Q {
        int l, r, id, ex;
    };
    const L &l;
    const TreeInfo &t;
    vector<int> fir, las, eul;
    vector<Q> q;

    explicit TreeMo(const L &l_) : l(l_), t(l_.t), fir(t.n), las(t.n) {
        build();
    }

    // ===== 双欧拉序：每个节点进入、离开各出现一次 =====
    void build() {
        eul.clear();
        q.clear();
        struct F { int u, it; };
        vector<F> stk{{t.root, 0}};
        eul.reserve(2 * t.n);
        fir[t.root] = eul.size();
        eul.push_back(t.root);
        while (!stk.empty()) {
            F &f{ stk.back() };
            if (f.it == int(t.g[f.u].size())) {
                las[f.u] = eul.size();
                eul.push_back(f.u);
                stk.pop_back();
                continue;
            }
            int v{ t.g[f.u][f.it ++].first };
            if (t.fa[v] != f.u) continue;
            fir[v] = eul.size();
            eul.push_back(v);
            stk.push_back({v, 0});
        }
    }

    // ===== 加入路径询问；edge=true 时按边权模式 =====
    int add(int u, int v, bool edge = false) {
        if (fir[u] > fir[v]) swap(u, v);
        int p{ l.lca(u, v) }, id{ int(q.size()) };
        if (p == u) q.push_back({fir[u], fir[v] + 1, id, edge ? p : -1});
        else q.push_back({las[u], fir[v] + 1, id, edge ? -1 : p});
        return id;
    }

    // ===== 莫队：add/del 维护节点状态，calc(id) 保存当前询问答案 =====
    template<class Add, class Del, class Calc>
    void run(Add add, Del del, Calc calc) const {
        if (q.empty()) return;
        vector<Q> a{ q };
        int bs{ max(1, int(eul.size() / sqrt(q.size()))) };
        sort(a.begin(), a.end(), [&](const Q &x, const Q &y) {
            int bx{ x.l / bs }, by{ y.l / bs };
            if (bx != by) return bx < by;
            return bx & 1 ? x.r > y.r : x.r < y.r;
        });

        vector<char> on(t.n);
        auto flip = [&](int u) {
            if (on[u]) del(u);
            else add(u);
            on[u] ^= 1;
        };

        int lp{}, rp{};
        for (auto [ql, qr, id, ex] : a) {
            while (lp > ql) flip(eul[-- lp]);
            while (rp < qr) flip(eul[rp ++]);
            while (lp < ql) flip(eul[lp ++]);
            while (rp > qr) flip(eul[-- rp]);

            if (ex != -1) flip(ex);
            calc(id);
            if (ex != -1) flip(ex);
        }
        while (lp < rp) flip(eul[lp ++]);
    }
};
```

##### 接口说明

###### 成员变量

- `fir[u]`：`u` 第一次进入 DFS 时的位置
- `las[u]`：离开 `u` 时第二次出现的位置
- `eul`：长度为 `2n` 的双欧拉序
- `Q::ex`：区间之外需要临时翻转一次的 LCA，`-1` 表示不需要
- `q`：全部离线路径询问

###### 接口

- `TreeMo(l)`：建立双欧拉序，$O(n)$
- `build()`：清空旧序列和旧询问，再建立双欧拉序；若原树换根，先重建绑定的 LCA
- `add(u,v,edge)`：加入路径询问并返回编号，LCA 查询复杂度取决于 `L`
- `run(add,del,calc)`：
  - `add(u)`：节点进入当前路径集合
  - `del(u)`：节点离开当前路径集合
  - `calc(id)`：保存编号为 `id` 的答案

##### 路径转换

设 `p=lca(u,v)`，且调整后 `fir[u]<=fir[v]`。

点权模式：

- `p=u`：使用 `[fir[u],fir[v]+1)`
- `p!=u`：使用 `[las[u],fir[v]+1)`，再额外加入 `p`

因为区间中出现两次的节点会被 `flip()` 抵消，只出现一次的节点恰好组成路径。

##### 边权模式

把边 `(fa[u],u)` 的信息挂在节点 `u` 上，然后：

```cpp
mo.add(u, v, true);
```

此时 LCA 对应节点会自动排除，所以当前集合恰好表示路径上的所有边。

##### 注意事项

- 本版只处理**静态点 / 边信息 + 离线路径询问**。
- 若查询之间还存在点权修改，需要扩展为带时间维的树上莫队，本板子不包含。
- `add()` / `del()` 必须互为逆操作。
- `calc(id)` 只读取当前状态，不修改莫队维护的信息。
- `run()` 结束时会恢复为空状态。
- `fir/las` 与 `TreeInfo::in/out` 不是同一种欧拉序：这里每个节点恰好出现两次。
- 查询很多但能够直接用 HLD + 数据结构在线完成时，不要为了“高级”硬上莫队；树上莫队主要适合不好用结合律数据结构维护、但单点增删很简单的统计问题。

##### 常见用法

###### 路径不同颜色数

```cpp
LCA lca(tr);
TreeMo mo(lca);

for (auto [u, v] : qry) mo.add(u, v);

vector<int> cnt(m), ans(qry.size());
int cur{};

auto add = [&](int u) {
    if (cnt[col[u]] ++ == 0) ++ cur;
};
auto del = [&](int u) {
    if (-- cnt[col[u]] == 0) -- cur;
};

mo.run(add, del, [&](int id) {
    ans[id] = cur;
});
```

##### 复杂度

设询问数为 $q$，一次 `add/del` 为 $O(T)$。块长取 max(1, floor(2n / sqrt(q)))，适应查询数远小于或大于 n 的情况；q=0 直接返回。

| 操作 | 复杂度 |
|---|---:|
| 双欧拉序 | $O(n)$ |
| 查询排序 | $O(q\log q)$ |
| 节点翻转总次数 | $O(n\sqrt q+q)$ |
| 总计 | $O(q\log q+(n\sqrt q+q)\cdot T)$ |
空间复杂度：$O(n+q)$
