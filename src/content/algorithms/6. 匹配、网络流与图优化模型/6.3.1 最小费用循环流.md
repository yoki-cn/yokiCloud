### 6.3.1 最小费用循环流
---
**依赖：** `6.3 最小费用流` 中的 `MinCostFlow`、`get_edge()`、`change_edge()` 与 `cancel_negative_cycles()`
```cpp
// ===== 依赖 MinCostFlow：最小费用循环流 =====
template<class Cap, class Cost>
Cost circulation_cost(const MinCostFlow<Cap, Cost> &mcf) {
    Cost ans{};
    for (int id = 0; 2 * id < int(mcf.e.size()); ++ id) {
        const auto &x{ mcf.e[2 * id] };
        ans += Cost(x.init - x.cap) * x.cost;
    }
    return ans;
}
// 当前状态必须是可行循环流，返回优化后的总费用
template<class Cap, class Cost>
Cost min_cost_circulation(MinCostFlow<Cap, Cost> &mcf) {
    Cost ans{ circulation_cost(mcf) };
    return ans + mcf.cancel_negative_cycles();
}
```
#### 原理
循环流要求每个点满足流量守恒，即
$$
\sum_{(v,u)} f_{vu}=\sum_{(u,v)} f_{uv}
$$
且每条边满足
$$
0\le f_e\le c_e
$$
若当前已经是一组可行循环流，则沿残量网络中的任意环增广都不会改变任何点的净流量
若某个残量环总费用为负，沿该环尽可能增广可以继续降低总费用，因此：
> [!tip]
> **可行循环流为最小费用循环流，当且仅当其残量网络不存在负费用环**

`cancel_negative_cycles()` 使用整数费用缩放恢复原点平衡并消除负环，作为循环流优化核心。实现与数值范围见 6.3。
#### 接口
- `circulation_cost(mcf)`：计算当前流的总费用，$O(m)$
- `min_cost_circulation(mcf)`：将**当前可行循环流**优化为最小费用循环流并返回最终总费用
- 求解后通过 `mcf.get_edge(id)` 恢复每条原边流量
#### 调用条件
- 调用 `min_cost_circulation()` 前，当前流必须满足所有点流量守恒
- 边流量必须满足 `0 <= flow <= capacity`
- 从刚建好的 `MinCostFlow` 直接调用时，初始零流天然是一组可行循环流
- 若使用 `change_edge()` 手动设置初始流，调用者必须保证设置后仍为可行循环流
#### 注意事项
- 普通只有上界 $0\le f\le cap$ 的循环流中，**零流永远可行**
- 因此若所有边费用均非负，最优解就是零流，总费用为 `0`
- 非平凡的普通最小费用循环流主要来自负费用环
- 若存在下界 $low\le f\le high$，零流不一定可行，应使用 **6.4.1 上下界最小费用流**
- 若存在点需求 / 供给约束，也应先通过超级源汇等方式构造一组可行流，再进行负环消除
- `cancel_negative_cycles()` 保持每个点的净流量不变，因此也可用于把某个固定净流量状态继续优化到最小费用
- `min_cost_circulation()` 会修改残量网络，再次调用时若已经不存在负环则费用不再变化
- 最大费用循环流可将所有费用取负，最后将答案取反
- `Cost` 必须能容纳 `Cap * Cost` 与总费用，范围较大时使用 `i128`
- 与普通 `flow()` 共用费用缩放核心；本接口保持各点净流量，不增加源汇流量
#### 常见用法
##### 从零流求最小费用循环流
```cpp
MinCostFlow<i64, i64> mcf(n);
for (auto [u, v, cap, cost] : edges) mcf.add_edge(u, v, cap, cost);
i64 ans{ min_cost_circulation(mcf) };
```
此时初始费用为 `0`，所以也可以直接写
```cpp
i64 ans{ mcf.cancel_negative_cycles() };
```
但统一使用 `min_cost_circulation()` 更适合之后复用到已有可行循环流
##### 恢复方案
```cpp
i64 ans{ min_cost_circulation(mcf) };
for (int id = 0; 2 * id < int(mcf.e.size()); ++ id) {
    auto [u, v, cap, flow, cost] = mcf.get_edge(id);
    // 原边 u -> v 使用 flow 单位流量
}
```
##### 从已有可行循环流继续优化
```cpp
// 已通过 change_edge() 等方式构造合法循环流
i64 before{ circulation_cost(mcf) };
i64 after{ min_cost_circulation(mcf) };
```
`after <= before`
##### 典型负环
```cpp
MinCostFlow<i64, i64> mcf(3);
mcf.add_edge(0, 1, 3, -5);
mcf.add_edge(1, 2, 3, 1);
mcf.add_edge(2, 0, 3, 1);
i64 ans{ min_cost_circulation(mcf) }; // -9
```
每绕环一单位费用为 $-5+1+1=-3$，容量限制允许绕 $3$ 单位，因此答案为 $-9$
#### 与普通最小费用流的关系
`flow(s,t,F)` 固定的是点的净流量：
$$
b_s=-F,\quad b_t=F
$$
循环流则所有点均有
$$
b_v=0
$$
两者的最优性条件本质相同：**残量网络不存在负费用环**
普通 `flow()` 已优化整个残量网络，包括与 `s` 无关的负环。以下重复优化保留接口用法，正常返回的改变量为 `0`：
```cpp
auto [f, cost] = mcf.flow(s, t, need);
if (f == need) cost += mcf.cancel_negative_cycles();
```
此时得到的是该固定 $s\to t$ 流量下的全局最小费用，而不是循环流问题本身
#### 复杂度
设有 $n$ 个点、$m$ 条逻辑边，$C$ 为最大单位费用绝对值。

| 操作 | 时间复杂度 |
|---|---:|
| `circulation_cost()` | $O(m)$ |
| `min_cost_circulation()` | $O(n^2m\log(2+nC))$ |

空间复杂度：$O(n+m)$。内部费用与盈余范围要求同 6.3，包装函数的费用累加还须能由 `Cost` 表示。
