### Gomory--Hu 最小割树
---
```cpp
// 依赖 6.2 Dinic<Cap>：add_edge()、max_flow()、min_cut()
template<class Cap = i64>
vector<tuple<int, int, Cap>> gomory_hu(int n, const vector<tuple<int, int, Cap>> &edges) {
    static_assert(numeric_limits<Cap>::is_integer && numeric_limits<Cap>::is_signed);
    vector<int> parent(n);
    vector<Cap> value(n);
    for (int s = 1; s < n; ++ s) {
        int t{ parent[s] };
        Dinic<Cap> flow(n);
        for (auto [u, v, cap] : edges) if (u != v) flow.add_edge(u, v, cap, cap);
        Cap cut{ flow.max_flow(s, t) };
        vector<char> side{ flow.min_cut(s) };
        // 与 s 同侧、且仍以 t 为父亲的后续点改挂到 s
        for (int i = s + 1; i < n; ++ i) {
            if (parent[i] == t && side[i]) parent[i] = s;
        }
        // t 的父亲也与 s 同侧时，需要旋转 parent 关系
        if (side[parent[t]]) {
            parent[s] = parent[t];
            parent[t] = s;
            value[s] = value[t];
            value[t] = cut;
        } else value[s] = cut;
    }
    vector<tuple<int, int, Cap>> tree;
    tree.reserve(max(0, n - 1));
    for (int u = 1; u < n; ++ u) tree.push_back({ u, parent[u], value[u] });
    return tree;
}
```
#### 原理
Gomory--Hu Tree 将一个无向容量图压缩为一棵带权树，使任意两点 `u,v` 满足
$$
\lambda(u,v)=\min_{e\in P(u,v)}w_e
$$
其中 $\lambda(u,v)$ 是原图的 `u-v` 最小割，`P(u,v)` 是割树上的唯一路径
算法维护 `parent[u]`，依次对 `s=1..n-1` 求 `s-parent[s]` 最小割，并利用最大流结束后的残量可达集合重新调整父亲关系，因此只需要 $n-1$ 次最大流
#### 接口说明
##### 返回值
`gomory_hu(n, edges)` 返回 `n-1` 条
```cpp
{u, parent[u], value[u]}
```
表示割树边 `u-parent[u]`，权值为 `value[u]`
原图任意两点 `s,t` 的最小割值等于割树上 `s-t` 路径中的最小边权
#### 注意事项
- 只适用于**无向非负容量图**
- 点编号为 `0base`
- 每条无向边使用 `flow.add_edge(u,v,cap,cap)` 建模
- 自环不影响任何两点最小割，直接忽略
- 平行边可以直接加入，无需预先合并
- 图可以不连通，此时不同连通块之间的最小割为 `0`，割树中会出现权值 `0` 的边
- 构造出的树不是原图子图，树边只编码割信息
- `flow.min_cut(s)` 必须返回最大流结束后残量网络中从 `s` 可达的点集
- 若 `6.2 Dinic` 中该接口命名为 `min_cut_side(s)`，这里对应改名即可
- 每轮都必须重新建立 Dinic，因为上一轮最大流已经修改了残量容量
- 容量和任意最小割值必须能放入 `Cap`
- `n <= 1` 时返回空树
- 全局最小割在 `n >= 2` 时等于割树所有边权的最小值
- 只需要一次全局最小割值时优先使用 `6.5 Stoer--Wagner`，无需跑 $n-1$ 次最大流
#### 常见用法
##### 建立割树
```cpp
auto tree = gomory_hu(n, edges);
vector<vector<pair<int, i64>>> g(n);
for (auto [u, v, cut] : tree) {
    g[u].push_back({ v, cut });
    g[v].push_back({ u, cut });
}
```
##### 单次查询两点最小割
查询不多时直接树上 DFS / BFS 即可
```cpp
auto query = [&](int s, int t) {
    vector<i64> mn(n, -1);
    queue<int> q;
    mn[s] = numeric_limits<i64>::max();
    q.push(s);
    while (!q.empty()) {
        int u{ q.front() };
        q.pop();
        if (u == t) return mn[u];
        for (auto [v, w] : g[u]) if (mn[v] == -1) {
            mn[v] = min(mn[u], w);
            q.push(v);
        }
    }
    return i64{};
};
```
##### 大量点对查询
对割树预处理倍增，维护跳跃过程中最小边权
```cpp
// query(u, v) = 割树路径 u-v 的最小边权
//             = 原图 u-v 最小割
```
也可以直接复用已有 HLD，在路径上维护区间最小值
##### 求全局最小割
```cpp
i64 ans{ numeric_limits<i64>::max() };
for (auto [u, v, cut] : tree) ans = min(ans, cut);
```
`n <= 1` 时需单独按约定处理
#### 复杂度
设一次最大流复杂度为 $MF(n,m)$
构造执行恰好 $n-1$ 次最大流，因此
$$
O(n\cdot MF(n,m))
$$
每轮重新建图还需要 $O(m)$，已被通常的最大流复杂度覆盖
割树自身空间复杂度为 $O(n)$，单轮最大流工作空间为 $O(n+m)$
> [!tip]
> `Stoer--Wagner` 回答的是“**整张图最容易在哪里切开**”，Gomory--Hu 则一次预处理后回答“**任意两点之间最少要切多少容量才能分开**”
