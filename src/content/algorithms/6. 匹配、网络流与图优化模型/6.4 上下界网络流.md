### 上下界网络流
---
可行性阶段从超级源实际只会发送 `need` 单位流，因此任何辅助边都不可能需要超过 `need` 的流量，这样既避免 `INF` 选择问题，也减少溢出风险  
上下界转化本身就是先强制发送下界，再把各点的“流入减流出”差额交给超级源汇修正
经典模板也分别通过可行流后继续增广求上下界最大 / 最小流
```cpp
// 依赖 6.2 Dinic<Cap>
template<class Cap = i64>
struct LowerBoundFlow {
    static_assert(numeric_limits<Cap>::is_integer && numeric_limits<Cap>::is_signed);
    struct Edge {
        int from, to;
        Cap low, high;
    };
    int n;
    vector<Edge> edges;
    vector<Cap> answer;
    explicit LowerBoundFlow(int n_) : n(n_) {}
    int add_edge(int u, int v, Cap low, Cap high) {
        edges.push_back({ u, v, low, high });
        return int(edges.size()) - 1;
    }
    bool feasible() { return solve(-1, -1, 0, nullopt).has_value(); }
    optional<Cap> feasible(int s, int t) { return solve(s, t, 0, nullopt); }
    optional<Cap> max_flow(int s, int t) { return solve(s, t, 1, nullopt); }
    optional<Cap> min_flow(int s, int t) { return solve(s, t, -1, nullopt); }
    optional<Cap> flow_with_value(int s, int t, Cap value) { return solve(s, t, 0, value); }
    Cap edge_flow(int id) const { return answer[id]; }
private:
    optional<Cap> solve(int s, int t, int type, optional<Cap> fixed) {
        bool has_st{ s != -1 };
        int ss{ n }, tt{ n + 1 };
        Dinic<Cap> flow(n + 2);
        vector<Cap> balance(n);
        vector<int> id(edges.size());
        // 先强制发送下界，只将 [0, high-low] 留给残量网络
        for (int i = 0; i < edges.size(); ++ i) {
            auto [u, v, low, high] = edges[i];
            id[i] = flow.add_edge(u, v, high - low);
            balance[u] -= low;
            balance[v] += low;
        }
        // 固定净 s->t 流量等价于额外固定 value 单位 t->s 流
        if (fixed) {
            balance[t] -= *fixed;
            balance[s] += *fixed;
        }
        Cap need{};
        for (Cap x : balance) if (x > 0) need += x;
        int back_ts{ -1 }, back_st{ -1 };
        if (has_st && !fixed) {
            // 两个方向同时存在，使基准可行流的净值可以为任意符号
            back_ts = flow.add_edge(t, s, need);
            back_st = flow.add_edge(s, t, need);
        }
        vector<int> auxiliary;
        for (int u = 0; u < n; ++ u) {
            if (balance[u] > 0) auxiliary.push_back(flow.add_edge(ss, u, balance[u]));
            else if (balance[u] < 0) auxiliary.push_back(flow.add_edge(u, tt, -balance[u]));
        }
        if (flow.max_flow(ss, tt) != need) {
            answer.clear();
            return nullopt;
        }
        for (int eid : auxiliary) flow.disable_edge(eid);
        Cap value{ fixed ? *fixed : 0 };
        if (has_st && !fixed) {
            value = flow.edge_flow(back_ts) - flow.edge_flow(back_st);
            flow.disable_edge(back_ts);
            flow.disable_edge(back_st);

            if (type > 0) value += flow.max_flow(s, t);
            if (type < 0) value -= flow.max_flow(t, s);
        }
        answer.resize(edges.size());
        for (int i = 0; i < edges.size(); ++ i) {
            answer[i] = edges[i].low + flow.edge_flow(id[i]);
        }
        return value;
    }
};
```
#### 原理
对原边
$$
low_e\le f_e\le high_e
$$
先固定发送 `low`，再令
$$
f_e=low_e+x_e,\qquad 0\le x_e\le high_e-low_e
$$
代码中的
```cpp
balance[u] -= low;
balance[v] += low;
```
维护的是下界流造成的
$$
balance_v=\text{流入}-\text{流出}
$$
于是：
- `balance[u] > 0`：当前流入过多，需要残量网络额外流出这么多，因此加入 `SS -> u`
- `balance[u] < 0`：当前流出过多，需要残量网络额外流入这么多，因此加入 `u -> TT`
- 所有 `SS` 出边均满流，当且仅当存在满足上下界与流量守恒的方案
#### 接口说明
##### 成员变量
- `edges[id]`：用户加入的第 `id` 条上下界边
- `answer[id]`：最近一次成功求解后，第 `id` 条原边实际流量
##### 接口
- `add_edge(u,v,low,high)`：加入流量范围 `[low,high]` 的有向边，返回原边编号，均摊 $O(1)$
- `feasible()`：判断并构造可行循环流
- `feasible(s,t)`：构造任意可行 `s-t` 流并返回其净流量，无解返回 `nullopt`
- `max_flow(s,t)`：返回最大可行净流量，无解返回 `nullopt`
- `min_flow(s,t)`：返回最小可行净流量，无解返回 `nullopt`
- `flow_with_value(s,t,value)`：构造净流量恰为 `value` 的可行流，`value` 可以为负
- `edge_flow(id)`：返回最近一次成功求解后原边流量，$O(1)$
这里统一定义
$$
\operatorname{value}=\text{s 的流出}-\text{s 的流入}
$$
因此一般有向图中的 `s-t` 流值允许为负；若题目保证 `s` 无入边、`t` 无出边，则自然非负
#### 固定流量为什么这样处理
要求净 `s -> t` 流量恰为 `value`，等价于额外加入一条固定流量为 `value` 的
$$
t\to s
$$
边，因此只需修改平衡量：
```cpp
balance[t] -= value;
balance[s] += value;
```
不需要真的插入固定边，所以 `value < 0` 也可以直接处理
#### 最大流与最小流
获得任意可行 `s-t` 流后先删除所有超级源汇边以及 `s <-> t` 辅助边
若当前净流量为 `value`：
```cpp
value += flow.max_flow(s, t); // 最大流
value -= flow.max_flow(t, s); // 最小流
```
原因是此时原边残量网络准确描述了所有保持上下界合法的调整方向
#### 注意事项
- 依赖 **6.2 Dinic 最大流** 的 `add_edge()`、`max_flow()`、`edge_flow()`、`disable_edge()`
- 点编号为 `0base`
- `Cap` 必须为有符号整数类型
- `add_edge()` 要求 `0 <= low <= high`
- 有源汇接口要求 `0 <= s,t < n` 且 `s != t`
- 每次求解都会从 `edges` 重新建立残量网络，因此同一对象可连续调用不同接口
- 每次成功求解都会覆盖 `answer`；求解失败会清空 `answer`
- `flow_with_value()` 中的 `value` 可以为负
- 可行阶段完成后必须删除超级源汇辅助边，否则之后的最大 / 最小增广会错误利用这些边
- 非固定有源汇问题还必须删除两条 `s <-> t` 辅助边
- 两条 `s <-> t` 辅助边容量取 `need` 即可，不需要额外设置 `INF`
- `Cap` 仍需容纳所有 `balance` 的和、流量与最终答案
- 平行边、自环均可正常处理，只要底层 Dinic 支持
- `edge_flow()` 只能在最近一次求解成功后读取
#### 常见用法
##### 最大上下界流并恢复方案
```cpp id="4cqtha"
LowerBoundFlow<i64> flow(n);
vector<int> id(m);
for (int i = 0; i < m; ++ i) id[i] = flow.add_edge(u[i], v[i], low[i], high[i]);
auto ans = flow.max_flow(s, t);
if (!ans) {
    cout << "No Solution\n";
} else {
    cout << *ans << '\n';
    for (int eid : id) cout << flow.edge_flow(eid) << '\n';
}
```
##### 无源汇可行环流
```cpp id="uobp8m"
LowerBoundFlow<i64> flow(n);
for (auto [u, v, low, high] : edges) flow.add_edge(u, v, low, high);
if (!flow.feasible()) {
    // 无可行环流
}
```
##### 任意可行有源汇流
```cpp id="dvb1tf"
auto value = flow.feasible(s, t);
if (value) {
    // *value 为该方案中 s 的净流出量
}
```
##### 固定净流量
```cpp id="5egm5p"
auto ans = flow.flow_with_value(s, t, need);
if (!ans) {
    // 不存在净流量恰为 need 的方案
}
```
负流量同样可以：
```cpp id="8smjgu"
auto ans = flow.flow_with_value(s, t, -need);
```
#### 复杂度
设原图有 $n$ 个点、$m$ 条边，辅助图有 $n+2$ 个点、$m+O(n)$ 条边

| 接口 | 最大流调用次数 |
|---|---:|
| `feasible()` | $1$ |
| `feasible(s,t)` | $1$ |
| `flow_with_value()` | $1$ |
| `max_flow()` | $2$ |
| `min_flow()` | $2$ |
建图与方案恢复均为 $O(n+m)$
若沿用 Dinic 的一般上界，一次完整求解写作 $O(n^2m)$ 量级，空间复杂度 $O(n+m)$
> [!tip]
> 这一版最值得保留的设计就是**允许有源汇净流量为负**  
> 很多传统板子只加 `t -> s` 一条辅助边，因此实际上默认答案非负
> 现在我们用双向辅助边把一般情形统一掉了，而且固定流量又直接通过 `balance` 处理
