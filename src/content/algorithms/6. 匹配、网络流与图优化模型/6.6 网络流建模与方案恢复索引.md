### 6.6 网络流建模与方案恢复索引
---
#### 模板选择

| 需求 | 优先使用 |
|---|---|
| 普通最大流 / `s-t` 最小割 | `6.2 Dinic` |
| 只求最大流值且 Dinic 较慢 | `6.2.1 HLPP` |
| 二分图最大匹配 | `6.1 Hopcroft--Karp` |
| 二分图最优匹配 / 指派 | `6.1.1 Hungarian--KM` |
| 一般图最大匹配 | `6.1.2 Blossom` |
| 一般图最大权匹配 | `6.1.3 Weighted Blossom` |
| 最小费用 `s-t` 流 | `6.3 MinCostFlow` |
| 最小费用循环流 | `6.3.1 最小费用循环流` |
| 上下界可行 / 最大 / 最小流 | `6.4 LowerBoundFlow` |
| 上下界最小费用流 | `6.4.1 LowerBoundMinCostFlow` |
| 无向全局最小割 | `6.5 Stoer--Wagner` |
| 无向任意点对最小割 | `6.5.1 Gomory--Hu` |
| 路径方案恢复 | `6.2 最大流扩展：流分解` |
#### 建模原子

| 题意 | 建模 |
|---|---|
| 某资源最多使用 `c` 次 | 容量 `c` |
| 某资源至多使用一次 | 容量 `1` |
| 某边必须至少使用 `low`、至多 `high` | 上下界 `[low,high]` |
| 某边必须恰好使用 `x` | 上下界 `[x,x]` |
| 使用一单位资源代价为 `cost` | 费用边 `(cap,cost)` |
| 选 `u` 必须选 `v` | `u -> v` 容量 `INF` |
| 点 `u` 最多经过 `c` 单位流 | 拆成 `u_in -> u_out`，容量 `c` |
| 一条边不能被最小割切断 | 容量 `INF` |
| 多个源 / 汇 | 建超级源 `SS` / 超级汇 `TT` |
| 要求流量守恒且有上下界 | `LowerBoundFlow` |
| 固定净 `s-t` 流量为 `F` | `flow_with_value(s,t,F)` |
| 要求恰好发送 `F` 单位最小费用流 | `MinCostFlow::flow(s,t,F)` 并检查返回流量 |
> [!tip]
> 网络流建模的核心通常只有三件事：**容量限制资源数量、最小割表达选择代价、费用表达每单位选择代价**

---
#### 多源多汇
增加超级源 `SS` 与超级汇 `TT`
```cpp
for (auto [s, cap] : sources) flow.add_edge(SS, s, cap);
for (auto [t, cap] : sinks) flow.add_edge(t, TT, cap);
```
若源 / 汇没有自身流量限制，可将容量取足够大的 `INF`

---
#### 无向容量边
若一条无向边总容量表示净流量满足
$$
|f_{uv}|\le c
$$
使用
```cpp
flow.add_edge(u, v, c, c);
```
若题意实际表示 `u -> v` 与 `v -> u` 各自拥有独立容量 `c`，则加入两条独立有向边
```cpp
flow.add_edge(u, v, c);
flow.add_edge(v, u, c);
```
两种模型在很多纯最大流问题中流值相同，但**逐边流量语义不同**，恢复方案时需要区分

---
#### 点容量与拆点
将原点 `u` 拆为
```text
u_in -> u_out
```
并令这条边容量等于点容量
原边
```text
u -> v
```
改为
```text
u_out -> v_in
```
若原边没有限制，容量设为 `INF`
##### 最小点割
```cpp
flow.add_edge(in(u), out(u), cost[u]);
flow.add_edge(out(u), in(v), INF);
```
通常源点、汇点本身不能删除，因此 `s_in -> s_out`、`t_in -> t_out` 取 `INF`
最大流后
```cpp
auto side = flow.min_cut(S);
```
若
```cpp
side[in(u)] && !side[out(u)]
```
则点 `u` 对应拆点边被割，即属于恢复出的点割
##### 点不相交路径
内部点拆边容量设为 `1`
```cpp
flow.add_edge(in(u), out(u), 1);
```
源汇通常使用 `INF`
最大流值即最大点不相交路径数，具体路径使用流分解恢复

---
#### 边不相交路径
每条可使用边容量设为 `1`
```cpp
flow.add_edge(u, v, 1);
```
最大流值即最大边不相交 `s-t` 路径数
方案使用
```cpp
auto paths = flow_decomposition(flow, s, t);
```
若只关心哪些边被使用，也可直接检查 `edge_flow(id)`

---
#### 最小割与删除问题
若删除原边 `e` 的代价为 `w_e`，直接令容量为 `w_e`
```cpp
flow.add_edge(u, v, w);
```
最大流值即最小删除代价
最大流结束后：
```cpp
auto side = flow.min_cut(s);
```
对有向边 `u -> v`
```cpp
side[u] && !side[v]
```
表示该边跨越最小割
对无向边只需判断
```cpp
side[u] != side[v]
```
> [!warning]
> `min_cut(s)` 只有在已经求出完整最大流后才代表最小割  
> 若 `max_flow(s,t,limit)` 因 `limit` 提前停止，则不能据此恢复最小割

---
#### 二选一 / 0-1 最小割模型
令 `side[v] = true` 表示选择状态 `0`，`false` 表示状态 `1`
若：
- 选择状态 `0` 的代价为 `c0`
- 选择状态 `1` 的代价为 `c1`
建边
```cpp
flow.add_edge(S, v, c1);
flow.add_edge(v, T, c0);
```
于是：
- `v` 位于源侧时切掉 `v -> T`，支付 `c0`
- `v` 位于汇侧时切掉 `S -> v`，支付 `c1`
若 `u,v` 状态不同需要额外支付 `w`，加入无向容量边
```cpp
flow.add_edge(u, v, w, w);
```
这类模型是大量“二选一 + 冲突代价”问题的基础

---
#### 最大权闭合图
每个点有权值 `w[u]`，选中 `u` 后要求所有后继依赖也必须选中
若 `u` 依赖 `v`：
```cpp
flow.add_edge(u, v, INF);
```
点权：
```cpp
if (w[u] > 0) flow.add_edge(S, u, w[u]);
else flow.add_edge(u, T, -w[u]);
```
设
```cpp
sum = Σ max(w[u], 0)
```
则
```text
最大闭合子图权值 = sum - maxflow
```
最大流后：
```cpp
auto side = flow.min_cut(S);
```
`side[u] == true` 的原图点即被选入最优闭合子图
##### 项目选择
“选择项目获得收益，但必须购买若干资源”直接视为闭合图：
```text
S -> 项目        收益
项目 -> 所需资源  INF
资源 -> T         成本
```
答案：
```text
总项目收益 - 最小割
```
源侧的项目和资源就是最终选择方案

---
#### `INF` 的选择
不要习惯性写
```cpp
numeric_limits<i64>::max()
```
更安全的方法是找出一个**有限解的确定上界 `B`**
```cpp
Cap INF{ B + 1 };
```
例如最大权闭合图可以取
```cpp
Cap sum{};
for (auto w : weight) if (w > 0) sum += w;
Cap INF{ sum + 1 };
```
因为存在代价至多 `sum` 的有限割，所以最优割绝不会切容量 `sum + 1` 的依赖边
若 `B + 1` 可能溢出，应直接换更宽类型

---
#### 二分图最大匹配
网络流建模：
```text
S -> 左部点      1
左部点 -> 右部点 1
右部点 -> T      1
```
最大流值等于最大匹配数
但普通二分图匹配应优先使用 `Hopcroft--Karp`，只有出现容量、费用、上下界等额外限制时再转网络流
方案恢复：
```cpp
int id{ flow.add_edge(u, v, 1) };
```
求最大流后若
```cpp
flow.edge_flow(id) == 1
```
则 `(u,v)` 被匹配

---
#### 二分图多重匹配 / $b$-Matching
若左点 `u` 最多匹配 `a[u]` 次，右点 `v` 最多匹配 `b[v]` 次：
```text
S -> u   a[u]
u -> v   边自身容量
v -> T   b[v]
```
原边容量为 `1` 时表示同一对点最多匹配一次
如果每条匹配还有费用或收益，直接把中间边换为费用边并使用 `MinCostFlow`

---
#### 二分图最小点覆盖
无权二分图有
$$
|\text{最小点覆盖}|=|\text{最大匹配}|
$$
最大流后设 `side` 为残量图从 `S` 可达点
则一个最小点覆盖为：
```text
左部中不可达点 + 右部中可达点
```
即
```cpp
if (!side[u]) cover.push_back(u); // u in L
if ( side[v]) cover.push_back(v); // v in R
```

---
#### 二分图最小权点覆盖
要求点权非负
```text
S -> 左点 u       w[u]
右点 v -> T       w[v]
左点 u -> 右点 v  INF
```
最小割值即最小权点覆盖
恢复方式仍为：
```text
左部不可达 + 右部可达
```
---
#### 二分图最大权独立集
对于非负点权：
$$
\text{最大权独立集}
=
\text{全部点权和}
-
\text{最小权点覆盖}
$$
方案恰好是最小点覆盖的补集：
```text
左部可达 + 右部不可达
```
##### 网格独立集
四邻接网格按棋盘奇偶染色后成为二分图，因此“选若干格子且相邻格不能同时选择”的最大权模型通常直接转最大权独立集

---
#### DAG 最小路径覆盖
把每个原点 `u` 拆为二分图中的 `u_L,u_R`
若 DAG 存在边
```text
u -> v
```
则加入
```text
u_L -> v_R
```
求二分图最大匹配 `M`
$$
\text{最小路径覆盖}=n-|M|
$$
拆左右点并使用最大匹配的 DAG 路径覆盖转化
##### 恢复路径
若匹配边为
```text
u_L -> v_R
```
则令
```cpp
nxt[u] = v;
pre[v] = u;
```
所有
```cpp
pre[u] == -1
```
的点都是一条覆盖路径的起点，沿 `nxt` 即可恢复整条路径
> [!warning]
> 上传资料中同时写有“一般无向图最小路径覆盖 = `n - 最大匹配数 / 2`”的表述
> 这个公式**不适用于一般无向图的顶点不交最小路径覆盖**，因此板子中只保留标准的 DAG 版本
##### 偏序最小链覆盖
若题目要求的是偏序链覆盖，应对“可比较关系”建二分图，而不是机械地只使用原图直接边
之后仍使用
$$
n-\text{最大匹配}
$$
---
#### 二分图指派 / 最小费用匹配
建图：
```text
S -> 左点       1, cost = 0
左点 -> 右点    1, cost = w
右点 -> T       1, cost = 0
```
要求恰好匹配 `k` 对：
```cpp
auto [f, cost] = mcf.flow(S, T, k);
if (f != k) {
    // 不存在大小为 k 的匹配
}
```
最大权匹配令中间边费用为 `-w`
恢复：
```cpp
auto [u, v, cap, used, cost] = mcf.get_edge(id);
if (used == 1) {
    // 选择了匹配边 u-v
}
```
资料中的“分配问题 / 二分图最优匹配”也是通过费用流处理
若是标准完整指派问题，应优先使用 Hungarian / KM，代码更短且更快

---
#### 运输 / 供需模型
供应点 `i` 有 `supply[i]`，需求点 `j` 有 `demand[j]`
```text
S -> 供应点 i       supply[i], 0
供应点 i -> 需求点 j 可运输量, transport_cost
需求点 j -> T       demand[j], 0
```
令
```cpp
Cap need = accumulate(demand.begin(), demand.end(), Cap{});
auto [f, cost] = mcf.flow(S, T, need);
```
`f == need` 才表示所有需求均被满足
如果供应和需求还有下界、固定量等约束，转 `LowerBoundMinCostFlow`

---
#### 固定数量的最小费用不相交路径
边不相交：
```text
原边容量 = 1
```
点不相交：
```text
u_in -> u_out 容量 = 1
```
边权作为费用，要求 `k` 条路径时：
```cpp
auto [f, cost] = mcf.flow(s, t, k);
```
只有 `f == k` 才存在 `k` 条满足条件的路径
资料中也单独收录了“最大权不相交路径”的费用流建模

---
#### 最大密度子图
经典定义：
$$
\rho(S)=\frac{|E(S)|}{|S|}
$$
资料中将其归为 **0-1 分数规划 + 网络流** 模型 【佚名B】算法模板
二分答案 `g`，判断是否存在
$$
|E(S)|-g|S|>0
$$
可以转为最大权闭合图：
- 每条原边建立一个“边点”，权值 `+1`
- 每个原顶点建立一个“点点”，权值 `-g`
- 边点向它的两个端点各连一条 `INF` 依赖边
- 若最大闭合子图权值 `> 0`，说明存在密度大于 `g` 的子图
若 Dinic 只支持整数容量，可将 `g=p/q` 后整体乘 `q`：
```text
边点权值 = q
顶点权值 = -p
```
最终源侧的原顶点即对应恢复出的候选子图

---
#### 上下界模型
原边：
$$
low\le f\le high
$$
直接使用：
```cpp
LowerBoundFlow<Cap> flow(n);
int id = flow.add_edge(u, v, low, high);
```
常见目标：
```cpp
flow.feasible();                    // 可行环流
flow.feasible(s, t);                // 任意可行 s-t 流
flow.max_flow(s, t);                // 最大净流量
flow.min_flow(s, t);                // 最小净流量
flow.flow_with_value(s, t, value);  // 固定净流量
```
恢复：
```cpp
Cap f = flow.edge_flow(id);
```
上下界转化的本质是先发送所有下界，再用超级源汇修正各点的流量不平衡

---
#### 上下界 + 费用
直接使用：
```cpp
LowerBoundMinCostFlow<Cap, Cost> flow(n);
```
对应：
```cpp
flow.circulation();
flow.flow_with_value(s, t, value);
flow.max_flow(s, t);
flow.min_flow(s, t);
```
其中 `max_flow()` / `min_flow()` 的目标是：
1. 先最大化 / 最小化净流量
2. 再在该流量值下最小化费用
方案直接读取：
```cpp
ans.flow[id]
```
---
#### 方案恢复速查

| 模型 | 恢复方法 |
|---|---|
| 普通边流量 | `flow.edge_flow(id)` |
| 费用流边流量 | `mcf.get_edge(id)` 中的 `used` |
| 上下界流量 | `LowerBoundFlow::edge_flow(id)` |
| 上下界费用流 | `Result::flow[id]` |
| 最小割两侧 | `flow.min_cut(s)` |
| 有向最小割边 | `side[u] && !side[v]` |
| 无向最小割边 | `side[u] != side[v]` |
| 最小点割 | `side[in(u)] && !side[out(u)]` |
| 最大权闭合图 | 原点位于源侧即被选择 |
| 二分图匹配 | 匹配边流量为 `1` |
| 二分图最小点覆盖 | 左部不可达 + 右部可达 |
| 二分图最大独立集 | 左部可达 + 右部不可达 |
| DAG 路径覆盖 | 匹配边建立 `nxt/pre` |
| `s-t` 路径方案 | 流分解 |
| Gomory--Hu 查询 | 割树路径最小边权 |
##### 最常用的两个恢复接口
```cpp
int id{ flow.add_edge(u, v, cap) };
Cap used{ flow.edge_flow(id) };
auto side = flow.min_cut(s);
```
建议建模时就保存逻辑边编号：
```cpp
vector<int> id(m);
for (int i = 0; i < m; ++ i) id[i] = flow.add_edge(u[i], v[i], cap[i]);
```
不要赛后再从邻接表位置猜原边

---
#### 常见错误
- **依赖边方向写反**：`选 u => 必须选 v` 应建 `u -> v` 的 `INF` 边
- **`INF` 不够大**：必须严格大于任意可能的有限最优割值
- **`INF` 过大导致溢出**：优先用“有限答案上界 + 1”
- **点限制直接放在所有邻边上**：点容量、点割、点不相交通常需要拆点
- **多源汇直接任选一个源汇**：应增加超级源汇
- **费用流要求恰好 `k` 却不检查返回流量**：必须判断 `f == k`
- **最大流尚未跑完就恢复最小割**：只有完整最大流后的残量可达集才是最小割
- **把反向残量边当原图边**：恢复原边时使用 `add_edge()` 返回的逻辑编号
- **把最大流方案直接当若干路径**：流中可能存在分叉或环，需要流分解
- **无向边建模语义混淆**：`add_edge(u,v,c,c)` 表示共享的无向容量，两个独立 `add_edge()` 表示两个方向各有容量
- **能用专门算法却强上网络流**：普通匹配用 HK、标准指派用 Hungarian、单次无向全局最小割用 Stoer--Wagner
> [!tip]
> 赛场看到模型时可以按这个顺序判断：**有没有“每个资源最多多少次” → 容量；有没有“选 A 必须选 B” → 最小割 / 闭合图；有没有“每单位代价” → 费用流；有没有“至少多少” → 上下界；有没有“点只能经过几次” → 拆点；最后再想怎么从残量图恢复方案**
