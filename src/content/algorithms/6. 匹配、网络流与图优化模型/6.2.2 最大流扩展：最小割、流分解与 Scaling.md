### 最大流扩展：最小割、流分解与 Scaling
---
**依赖：** `6.2 Dinic 最大流`，以下内容均作为 Dinic 的扩展使用，不重复建图与普通最大流代码
#### 最小割恢复
在已经求出最大流后，从源点 `s` 在残量网络中继续沿正残量边搜索，可达点构成最小割的源点侧 $S$，其余点构成汇点侧 $T$，这也是常用 Dinic 实现恢复最小割的方法
将以下函数加入 `Dinic`：
```cpp
// ===== 以下函数可直接删除：最小割恢复 =====
vector<char> min_cut_side(int s) const {
    vector<char> vis(n);
    queue<int> q;
    vis[s] = true;
    q.push(s);
    while (!q.empty()) {
        int u{ q.front() };
        q.pop();
        for (int id : g[u]) if (e[id].cap > 0 && !vis[e[id].to]) {
            vis[e[id].to] = true;
            q.push(e[id].to);
        }
    }
    return vis;
}
// 返回跨越 S -> T 的原始有容量半边编号，即 e[] 中的下标
vector<int> min_cut_edges(int s) const {
    vector<char> side{ min_cut_side(s) };
    vector<int> ans;
    for (int id = 0; id < int(e.size()); ++ id) {
        const Edge &x{ e[id] };
        if (x.init > 0 && side[x.from] && !side[x.to]) ans.push_back(id);
    }
    return ans;
}
```
##### 接口
- `min_cut_side(s)`：返回源点侧标记，`side[u] = true` 表示 `u` 属于最小割源点侧，$O(n+m)$
- `min_cut_edges(s)`：返回最小割中所有原始有容量半边在 `e[]` 中的编号，$O(n+m)$
- 对普通 `add_edge(u,v,cap)`，正向边编号为 `2 * id`；若使用了非零 `rcap`，反向半边也可能属于割
##### 常见用法
```cpp
flow.max_flow(s, t);
auto side = flow.min_cut_side(s);
for (int u = 0; u < n; ++ u) {
    if (side[u]) {
        // u 位于源点侧 S
    } else {
        // u 位于汇点侧 T
    }
}
```
恢复割边：
```cpp
auto cut = flow.min_cut_edges(s);
for (int eid : cut) {
    auto [u, v] = pair{ flow.e[eid].from, flow.e[eid].to };
    // 原图割边 u -> v
}
```
> [!warning]
> 只有在 `max_flow(s,t)` 已经增广到最大流后，残量可达集才对应最小割  
> 若使用 `limit` 提前停止，不能据此恢复最小割
#### 流分解
一个合法 $s-t$ 流可以分解为若干条带流量的 $s-t$ 路径，再加若干个带流量的环
多数方案输出题只需要路径部分，环流不影响 $s-t$ 流值，因此默认不返回环；需要完整分解时令 `keep_cycles = true`
```cpp
template<class Cap>
struct FlowPart {
    Cap flow{};
    vector<int> vertices; // 依次经过的点，环首尾相同
    vector<int> edges;    // 对应 Dinic::e[] 中的半边编号
    bool cycle{};
};
template<class Cap>
vector<FlowPart<Cap>> flow_decomposition(const Dinic<Cap> &mf, int s, int t, bool keep_cycles = false) {
    struct Arc {
        int to, eid;
        Cap flow;
    };
    int n{ mf.n };
    vector<vector<int>> g(n);
    vector<Arc> a;
    auto add = [&](int u, int v, int eid, Cap f) {
        g[u].push_back(a.size());
        a.push_back({ v, eid, f });
    };
    // 每对残量边恢复一个净流方向
    for (int id = 0; 2 * id < int(mf.e.size()); ++ id) {
        const auto &x{ mf.e[2 * id] };
        Cap f{ x.init - x.cap };
        if (f > 0) add(x.from, x.to, 2 * id, f);
        else if (f < 0) add(x.to, x.from, 2 * id + 1, -f);
    }
    vector<FlowPart<Cap>> ans;
    // 只提取净 s->t 流量；经过源汇的环流不能计入路径流值。
    Cap remaining{};
    if (s != t) for (int id = 0; 2 * id < int(mf.e.size()); ++ id) {
        const auto &x{ mf.e[2 * id] };
        Cap f{ x.init - x.cap };
        if (x.from == s) remaining += f;
        if (x.to == s) remaining -= f;
    }
    assert(remaining >= 0);
    while (remaining > 0) {
        vector<int> pre(n, -1), pe(n, -1);
        queue<int> q;
        pre[s] = s;
        q.push(s);
        while (!q.empty() && pre[t] == -1) {
            int u{ q.front() };
            q.pop();
            for (int id : g[u]) if (a[id].flow > 0 && pre[a[id].to] == -1) {
                pre[a[id].to] = u;
                pe[a[id].to] = id;
                q.push(a[id].to);
            }
        }
        assert(pre[t] != -1); // 合法非负净流必有足够的正流路径
        vector<int> path;
        for (int v = t; v != s; v = pre[v]) path.push_back(pe[v]);
        ranges::reverse(path);
        Cap f{ remaining };
        for (int id : path) f = min(f, a[id].flow);
        remaining -= f;
        FlowPart<Cap> part;
        part.flow = f;
        part.vertices.push_back(s);
        for (int id : path) {
            a[id].flow -= f;
            part.edges.push_back(a[id].eid);
            part.vertices.push_back(a[id].to);
        }
        ans.push_back(move(part));
    }
    if (!keep_cycles) return ans;
    // 剩余正流一定是 circulation，继续提取环
    while (true) {
        int start{ -1 };
        for (int u = 0; u < n && start == -1; ++ u) {
            for (int id : g[u]) if (a[id].flow > 0) {
                start = u;
                break;
            }
        }
        if (start == -1) break;
        vector<int> pos(n, -1), vertices, path;
        int u{ start };
        while (pos[u] == -1) {
            pos[u] = vertices.size();
            vertices.push_back(u);
            int id{ -1 };
            for (int x : g[u]) if (a[x].flow > 0) {
                id = x;
                break;
            }
            assert(id != -1);
            path.push_back(id);
            u = a[id].to;
        }
        int k{ pos[u] };
        Cap f{ numeric_limits<Cap>::max() };
        for (int i = k; i < path.size(); ++ i) f = min(f, a[path[i]].flow);
        FlowPart<Cap> part;
        part.flow = f;
        part.cycle = true;
        for (int i = k; i < vertices.size(); ++ i) part.vertices.push_back(vertices[i]);
        part.vertices.push_back(u);
        for (int i = k; i < path.size(); ++ i) {
            a[path[i]].flow -= f;
            part.edges.push_back(a[path[i]].eid);
        }
        ans.push_back(move(part));
    }
    return ans;
}
```
##### 接口
- `flow_decomposition(flow,s,t)`：分解为若干条 $s\to t$ 路径，忽略剩余环流
- `flow_decomposition(flow,s,t,true)`：完整分解为路径与环
- `part.flow`：该路径或环携带的流量
- `part.vertices`：点序列
- `part.edges`：对应 `Dinic::e[]` 的半边编号，可处理平行边
- `part.cycle`：是否为环流分量
- `eid / 2`：对应 `add_edge()` 返回的逻辑边编号
- `eid & 1`：是否使用该逻辑边的反向半边
##### 常见用法
```cpp
flow.max_flow(s, t);
auto parts = flow_decomposition(flow, s, t);
for (auto &[f, vertices, edges, cycle] : parts) {
    // 一条流量为 f 的 s -> t 路径
}
```
完整分解：
```cpp
auto parts = flow_decomposition(flow, s, t, true);
for (auto &part : parts) {
    if (part.cycle) {
        // 环流
    } else {
        // s -> t 路径流
    }
}
```
##### 注意事项
- 应在一个**合法流状态**上调用，通常就是 `max_flow()` 之后
- 要求净 s-t 流值非负；s == t 时按循环流处理，仅 keep_cycles=true 时恢复环
- 函数复制当前流量，不修改原 Dinic
- 使用 `init - cap` 恢复每对残量边上的净流，因此也兼容 `rcap != 0`
- 默认去掉环流后得到的路径流总和仍等于原 $s-t$ 流值
- 若只需要每条原边的流量，无需做流分解，直接读取 `e[2 * id].init - e[2 * id].cap`
最坏情况下至多提取 $O(m)$ 个分量，当前实现时间复杂度 $O(m(n+m))$，额外空间 $O(n+m)$
#### Dinic Capacity Scaling
现在 Dinic 的 `bfs(s,t,scale)` 已经预留了残量容量阈值，因此不需要再维护一套 Scaling 模板，只新增下面的接口即可
Scaling 从不超过最大残量容量的最高二进制位开始，只让 BFS 使用残量容量至少为 `scale` 的边，处理完后不断减半；KACTL 的 Dinic 也采用这种容量 Scaling，并给出 $O(nm\log U)$ 的复杂度，其中 $U$ 为最大容量
```cpp
// ===== 以下函数可直接删除：Capacity Scaling =====
Cap max_flow_scaling(int s, int t, Cap limit = numeric_limits<Cap>::max()) {
    Cap mx{};
    for (const Edge &x : e) mx = max(mx, x.cap);
    if (s == t || mx == 0 || limit == 0) return 0;
    Cap scale{ 1 };
    while (scale <= mx / 2) scale <<= 1;
    Cap ans{};
    for (; scale && ans < limit; scale >>= 1) {
        while (ans < limit && bfs(s, t, scale)) {
            ranges::fill(it, 0);
            while (ans < limit) {
                Cap f{ dfs(s, t, limit - ans, scale) };
                if (!f) break;
                ans += f;
            }
        }
    }
    return ans;
}
```
这里要求原 Dinic 的 `bfs()` 使用：
```cpp
if (e[id].cap >= scale && level[e[id].to] == -1) {
    // ...
}
```
普通 `max_flow()` 调用 `bfs(s,t)`，默认 `scale = 1`，因此不会增加普通版本的额外代码路径
##### 接口
- `max_flow_scaling(s,t)`：使用 Capacity Scaling 增广到最大流
- `max_flow_scaling(s,t,limit)`：最多再增广 `limit`
- 返回值与普通 `max_flow()` 一样，是**本次调用新增的流量**
- 可以在已有合法残量状态上继续调用
##### 注意事项
- 只适用于整数容量
- $U$ 为当前残量网络中的最大容量
- 容量范围很小时 Scaling 未必比普通 Dinic 快，甚至可能因为多轮阈值扫描增加常数
- 容量跨度很大、普通 Dinic 表现较差时值得尝试
- 若已经准备 HLPP，Scaling 属于可选性能工具，不建议默认替换普通 Dinic
- Scaling 改变的只是寻找增广路的顺序，最终残量网络仍是普通合法最大流，因此最小割、边流量、流分解等接口都可以正常使用
#### 复杂度

| 功能 | 时间复杂度 | 额外空间 |
|---|---:|---:|
| `min_cut_side()` | $O(n+m)$ | $O(n)$ |
| `min_cut_edges()` | $O(n+m)$ | $O(n)$ |
| `flow_decomposition()` | $O(m(n+m))$ | $O(n+m)$ |
| `max_flow_scaling()` | $O(nm\log U)$ | 沿用 Dinic |

> [!tip]
> 这三个扩展的定位可以很明确：**最小割负责恢复割方案，流分解负责恢复路径方案，Scaling 只负责换一种增广顺序提速**
