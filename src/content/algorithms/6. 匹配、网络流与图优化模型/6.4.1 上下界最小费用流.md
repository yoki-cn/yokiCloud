### 上下界最小费用流
---
传统上下界可行流本身就是先固定下界，再通过超级源汇修正各点的流量不平衡
这里在得到任意满足目标净流量的可行流后，再利用负环消圈优化费用即可
```cpp
// 依赖 6.4 LowerBoundFlow<Cap> 与 6.3 MinCostFlow<Cap, Cost>
template<class Cap = i64, class Cost = i64>
struct LowerBoundMinCostFlow {
    static_assert(numeric_limits<Cap>::is_integer && numeric_limits<Cap>::is_signed);
    static_assert(numeric_limits<Cost>::is_integer && numeric_limits<Cost>::is_signed);
    struct Edge {
        int from, to;
        Cap low, high;
        Cost cost;
    };
    struct Result {
        bool feasible{};
        Cap value{};
        Cost cost{};
        vector<Cap> flow;
    };
    int n, sc{ 8 };
    bool upd{};
    vector<Edge> edges;
    explicit LowerBoundMinCostFlow(int n_) : n(n_) {}
    int add_edge(int u, int v, Cap low, Cap high, Cost cost) {
        edges.push_back({ u, v, low, high, cost });
        return int(edges.size()) - 1;
    }
    Result circulation() const { return solve(-1, -1, 0, nullopt); }
    Result flow_with_value(int s, int t, Cap value) const { return solve(s, t, 0, value); }
    // ===== 以下函数可直接删除：按流量优先，再最小化费用 =====
    Result max_flow(int s, int t) const { return solve(s, t, 1, nullopt); }
    Result min_flow(int s, int t) const { return solve(s, t, -1, nullopt); }

private:
    Result solve(int s, int t, int type, optional<Cap> fixed) const {
        // 第一步：忽略费用，构造满足上下界及目标净流量的任意可行流
        LowerBoundFlow<Cap> feasible(n);
        for (const Edge &x : edges) feasible.add_edge(x.from, x.to, x.low, x.high);
        Cap value{};
        if (s == -1) {
            if (!feasible.feasible()) return {};
        } else {
            optional<Cap> res;
            if (fixed) res = feasible.flow_with_value(s, t, *fixed);
            else if (type > 0) res = feasible.max_flow(s, t);
            else res = feasible.min_flow(s, t);
            if (!res) return {};
            value = *res;
        }
        // 第二步：装入费用残量网络，保持净流量不变并消除所有负费用环
        MinCostFlow<Cap, Cost> mcf(n);
        mcf.upd = upd;
        mcf.sc = sc;
        vector<int> id(edges.size());
        Cost total{};
        for (int i = 0; i < int(edges.size()); ++ i) {
            const auto &[u, v, low, high, cost] = edges[i];
            Cap f{ feasible.edge_flow(i) };
            id[i] = mcf.add_edge(u, v, high - low, cost);
            mcf.change_edge(id[i], high - low, f - low);
            total += Cost(f) * cost;
        }
        total += mcf.cancel_negative_cycles();
        vector<Cap> answer(edges.size());
        for (int i = 0; i < int(edges.size()); ++ i) {
            auto [u, v, cap, used, cost] = mcf.get_edge(id[i]);
            answer[i] = edges[i].low + used;
        }
        return { true, value, total, move(answer) };
    }
};
```
#### 原理
第一阶段只处理可行性
对于原边
$$
low_e\le f_e\le high_e
$$
先使用 `LowerBoundFlow` 得到满足上下界以及指定净流量约束的任意可行流 `f`
第二阶段令
$$
x_e=f_e-low_e
$$
于是
$$
0\le x_e\le high_e-low_e
$$
代码用
```cpp
mcf.add_edge(u, v, high - low, cost);
mcf.change_edge(id, high - low, f - low);
```
直接把当前 `x` 装入费用残量网络
虽然 `x` 本身未必满足普通循环流意义下的流量守恒，但它的各点净流量已经固定  
任意两个满足同一上下界与同一净流量约束的可行解之差一定是一个 circulation，因此所有进一步调整都可以表示为残量网络中的环流
若残量网络还存在负费用环，就能沿该环增广并降低总费用  
不存在负费用环时即达到该净流量约束下的全局最优费用
#### 接口
- `LowerBoundMinCostFlow(n)`：建立 `n` 点空网络，$O(n)$
- `add_edge(u,v,low,high,cost)`：加入流量范围 `[low,high]`、单位费用 `cost` 的有向边，返回原边编号
- `circulation()`：求最小费用可行环流
- `flow_with_value(s,t,value)`：求净 `s-t` 流量恰为 `value` 的最小费用流，`value` 可以为负
- `max_flow(s,t)`：先最大化净 `s-t` 流量，再在所有最大流中最小化费用
- `min_flow(s,t)`：先最小化净 `s-t` 流量，再在所有最小流中最小化费用
- `Result::feasible`：是否存在可行方案
- `Result::value`：最终 `s` 的净流出量，`circulation()` 中为 `0`
- `Result::cost`：最小总费用
- `Result::flow[id]`：第 `id` 条原边最终实际流量
#### 注意事项
- 本板复用 `6.4 LowerBoundFlow` 求可行解，再复用 `6.3 MinCostFlow::cancel_negative_cycles()` 优化费用，不维护第三套独立费用流实现
- 要求 `0 <= low <= high`
- 有源汇接口要求 `s != t`
- `Cap` 与 `Cost` 均应使用有符号整数类型
- `flow_with_value()` 中 `value` 可以为负，含义仍是 `s` 的净流出量
- `max_flow()` / `min_flow()` 是**字典序目标**，先优化流量值，再在该流量下最小化费用
- 第一步得到什么可行流不影响最终答案，第二步会在具有相同点净流量的所有可行流之间优化
- 保持指定净流量时调用 `cancel_negative_cycles()`；`flow(s,t)` 还会改变流量值，不能替代固定流量的费用优化
- `Result::feasible == false` 时不要读取 `value`、`cost` 或 `flow`
- 单位费用允许为负，只要所有容量上界有限，最优费用仍有有限下界
- `Cost` 必须能容纳 `flow * cost`、负环费用变化与最终总费用，范围大时使用 `i128`
- 普通无上下界 `s-t` 最小费用流直接使用 `6.3 MinCostFlow`
- 费用优化复用 6.3 的整数费用缩放，包装接口不增加另一套费用流实现；内部盈余、缩放费用与势能的数值范围同 6.3
#### 常见用法
##### 固定流量最小费用
```cpp
LowerBoundMinCostFlow<i64, i64> flow(n);
for (int i = 0; i < m; ++ i) {
    flow.add_edge(u[i], v[i], low[i], high[i], cost[i]);
}
auto ans = flow.flow_with_value(s, t, need);
if (!ans.feasible) {
    cout << "No Solution\n";
} else {
    cout << ans.cost << '\n';
    for (i64 f : ans.flow) cout << f << '\n';
}
```
##### 最小费用可行环流
```cpp
auto ans = flow.circulation();
if (ans.feasible) cout << ans.cost << '\n';
```
##### 上下界最小费用最大流
```cpp
auto ans = flow.max_flow(s, t);
if (ans.feasible) {
    cout << ans.value << ' ' << ans.cost << '\n';
}
```
不再需要先额外建立一个 `LowerBoundFlow` 求最大值再调用 `flow_with_value()`
##### 上下界最小费用最小流
```cpp
auto ans = flow.min_flow(s, t);
if (ans.feasible) {
    cout << ans.value << ' ' << ans.cost << '\n';
}
```
#### 复杂度
设原图为 $n$ 点、$m$ 边，最大单位费用绝对值为 $C$

| 接口 | 可行流阶段 | 费用优化 |
|---|---:|---:|
| `circulation()` | 一次 Dinic | $O(n^2m\log(2+nC))$ |
| `flow_with_value()` | 一次 Dinic | $O(n^2m\log(2+nC))$ |
| `max_flow()` | 至多两次 Dinic | $O(n^2m\log(2+nC))$ |
| `min_flow()` | 至多两次 Dinic | $O(n^2m\log(2+nC))$ |
若把 `LowerBoundFlow` 的复杂度记为 $T_{\mathrm{flow}}$，则总复杂度可写为
$$
O(T_{\mathrm{flow}}+n^2m\log(2+nC))
$$
空间复杂度为 $O(n+m)$
#### 常用方法：开启价格更新
包装直接把 `upd/sc` 传给 6.3，默认关闭价格更新、缩放因子为 `8`，对全部求解接口生效。
```cpp
LowerBoundMinCostFlow<i64, i128> g(2);
g.upd = true;
g.sc = 4; // 可省略
// 两条边构成循环流，下界要求至少流 1，最优流量为 3
g.add_edge(0, 1, 1, 3, -2);
g.add_edge(1, 0, 1, 3, 1);
auto ans = g.circulation();
assert(ans.feasible && ans.cost == -3);
```
价格更新可能减少重标号，也会增加最短路开销；开启前后分别测试，不能据此放宽数值范围。细节见 6.3 常用方法。
