### PBDS 常见用法
#### 公共头文件
```cpp
#include <ext/pb_ds/assoc_container.hpp>
#include <ext/pb_ds/tree_policy.hpp>
#include <ext/pb_ds/trie_policy.hpp>
#include <ext/pb_ds/priority_queue.hpp>
using namespace __gnu_pbds;
```
GNU 环境也可直接使用
```cpp
#include <bits/extc++.h>
using namespace __gnu_pbds;
```
### 顺序统计红黑树
---
基于 `rb_tree_tag`，主要用于动态排名、第 $k$ 小等，通常是 PBDS 中最常用的结构
```cpp
template<class T, class C = less<T>>
using RBT = tree<T, null_type, C, rb_tree_tag, tree_order_statistics_node_update>;
```
#### 接口
只记录普通平衡树之外的接口
- `t.order_of_key(x)`：严格小于 `x` 的元素个数
- `t.find_by_order(k)`：第 `k` 小，`0base`，越界返回 `end()`
- `t.split(x, b)`：`less` 下将 `> x` 的部分移入 `b`
- `t.join(b)`：将 `b` 合入 `t`，成功后 `b` 为空
#### 常见用法
第 `k` 小，`k` 为 `0base`
```cpp
auto it = t.find_by_order(k);
if (it != t.end()) {
    auto x = *it;
}
```
严格小于 `x` 的个数
```cpp
int k = t.order_of_key(x);
```
`x` 的 `1base` 排名
```cpp
int rk = t.order_of_key(x) + 1;
```
严格前驱
```cpp
int k = t.order_of_key(x);
if (k) {
    auto pre = *t.find_by_order(k - 1);
}
```
按值切树
```cpp
RBT<int> a, b;
a.split(x, b);
// a: <= x
// b: > x
```
恢复
```cpp
a.join(b);
```
#### 多重集合
不要使用 `less_equal`
```cpp
RBT<int, less_equal<int>> t; // 不要这样写
```
比较器必须满足严格弱序，多重元素统一加入唯一编号
```cpp
using P = pair<i64, int>;
RBT<P> t;
int id{};
t.insert({x, id++});
```
建议保证 `id >= 0`，查询时用 `-1` 和足够大的值作为边界
```cpp
constexpr int INF = 1E9;
```
`< x`
```cpp
int c = t.order_of_key({x, -1});
```
`<= x`
```cpp
int c = t.order_of_key({x, INF});
```
`== x`
```cpp
int c = t.order_of_key({x, INF}) - t.order_of_key({x, -1});
```
第 `k` 小，`k` 为 `1base`
```cpp
i64 x = t.find_by_order(k - 1)->first;
```
严格前驱
```cpp
int k = t.order_of_key({x, -1});
if (k) {
    i64 pre = t.find_by_order(k - 1)->first;
}
```
严格后继
```cpp
int k = t.order_of_key({x, INF});
if (k < int(t.size())) {
    i64 suf = t.find_by_order(k)->first;
}
```
删除任意一个 `x`
```cpp
auto it = t.lower_bound({x, -1});
if (it != t.end() && it->first == x) t.erase(it);
```
精确删除时保存编号
```cpp
int p = id++;
t.insert({x, p});
t.erase({x, p});
```
#### 注意事项
- `join` 要求两棵树值域完全分离，即一棵整体小于另一棵
- `split/join` 是 PBDS 的实现接口，不建议在复杂度证明中直接当作手写红黑树的标准 $O(\log n)$ 操作
- 只需要排名和第 $k$ 小一般优先使用 `rb_tree_tag`
#### 复杂度
- 插入、删除、查找：$O(\log n)$
- `order_of_key`：$O(\log n)$
- `find_by_order`：$O(\log n)$

### Splay Tree
---
PBDS 自带按键维护的 Splay，可省掉只需要集合操作、自调整访问和按键切分时的手写 Splay
```cpp
template<class T, class C = less<T>>
using SPT = tree<T, null_type, C, splay_tree_tag, tree_order_statistics_node_update>;
```
如果不需要排名可缩短为
```cpp
template<class T, class C = less<T>>
using SPT = tree<T, null_type, C, splay_tree_tag>;
```
#### 接口
启用 `tree_order_statistics_node_update` 后
- `t.order_of_key(x)`：严格小于 `x` 的元素个数
- `t.find_by_order(k)`：第 `k` 小
- `t.split(x, b)`：按键切成 `<= x` 与 `> x`
- `t.join(b)`：合并两个值域完全分离的 Splay
#### 常见用法
按值切分
```cpp
SPT<int> a, b;
a.split(x, b);
```
处理后重新合并
```cpp
a.join(b);
```
带排名
```cpp
int rk = t.order_of_key(x);
auto it = t.find_by_order(k);
```
#### 注意事项
- 这是**按键排序的 Splay**，不是隐式 Splay
- 不能直接完成区间翻转、区间加法、序列搬移等隐式 Splay 操作
- 连续访问相近或重复元素时才较可能发挥 Splay 的局部性优势
- 普通动态排名问题优先 `rb_tree_tag`
#### 复杂度
- 查找、插入、删除：均摊 $O(\log n)$
- 顺序统计：均摊 $O(\log n)$
- 单次操作最坏可退化到 $O(n)$

### Ordered Vector Tree
---
底层为 `ov_tree_tag`，本质更接近有序连续数组，查询多、修改很少时可以使用
```cpp
template<class T, class C = less<T>>
using OVT = tree<T, null_type, C, ov_tree_tag, tree_order_statistics_node_update>;
```
#### 接口
- `t.order_of_key(x)`：严格小于 `x` 的元素个数
- `t.find_by_order(k)`：第 `k` 小
- `t.split(x, b)`：按键切分
- `t.join(b)`：合并值域完全分离的两棵树
#### 常见用法
大量排名查询，数据只进行少量修改
```cpp
OVT<int> t;
for (int x : a) t.insert(x);
int rk = t.order_of_key(x);
int v = *t.find_by_order(k);
```
#### 注意事项
- 插入、删除需要移动大量元素
- 动态修改多时不要使用
- 修改可能导致大量迭代器失效
- 如果数据完全静态，直接排序 `vector` 往往更简单
#### 复杂度
- 查询、顺序统计：$O(\log n)$
- 插入、删除：$O(n)$

### Patricia Trie
---
PBDS 自带压缩字典树，最有价值的是直接提供前缀范围查询，可省掉一整份 Trie
```cpp
using PT = trie<string, null_type, trie_string_access_traits<>,
    pat_trie_tag, trie_prefix_search_node_update>;
```
#### 接口
除普通集合操作外主要使用
- `t.prefix_range(s)`：返回所有以 `s` 为前缀的字符串区间
- `t.split(s, b)`：字典序 `> s` 的部分移入 `b`
- `t.join(b)`：合并两个字典序值域分离的 Trie
`prefix_range` 返回
```cpp
pair<PT::iterator, PT::iterator>
```
#### 常见用法
插入字符串
```cpp
PT t;
t.insert("abc");
t.insert("abd");
t.insert("acd");
```
枚举所有以 `"ab"` 开头的字符串
```cpp
auto [l, r] = t.prefix_range("ab");
for (auto it = l; it != r; ++ it) {
    cout << *it << '\n';
}
```
判断是否存在某个前缀
```cpp
auto [l, r] = t.prefix_range(s);
if (l != r) {}
```
统计前缀匹配数只能遍历区间
```cpp
auto [l, r] = t.prefix_range(s);
int c{};
for (; l != r; ++ l) ++ c;
```
若题目需要大量前缀计数，应手写带 `cnt` 的 Trie，而不是这样遍历
#### 注意事项
- `prefix_range` 是 Patricia Trie 最值得使用的功能
- 字符串很多且字符集小时，手写数组 Trie 往往更快
- PBDS Trie 常数和内存开销不小
- `trie_order_statistics_node_update` 在部分新 GCC + C++20 环境存在兼容问题，不建议作为赛场板子依赖
#### 复杂度
设字符串长度为 $L$
- 查找、插入、删除通常与 $L$ 相关
- `prefix_range(p)` 定位与前缀长度相关
- 枚举额外需要 $O(ans)$

### GP Hash Table
---
开放寻址哈希表，主要价值是较小常数，不重复记录标准哈希表已有接口
```cpp
template<class K, class V, class H = hash<K>>
using HT = gp_hash_table<K, V, H>;
```
#### 接口
需要特别注意的接口差异
```cpp
if (mp.find(x) != mp.end()) {}
```
默认不要写
```cpp
mp.count(x);
mp.reserve(n);
mp.resize(n);
```
这些接口不能直接按 `unordered_map` 的习惯使用
#### 常见用法
```cpp
HT<i64, int> mp;
++ mp[x];
```
配合防卡哈希
```cpp
struct H {
    static u64 f(u64 x) {
        x += 0x9e3779b97f4a7c15ULL;
        x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9ULL;
        x = (x ^ (x >> 27)) * 0x94d049bb133111ebULL;
        return x ^ (x >> 31);
    }
    size_t operator()(u64 x) const {
        static const u64 s = chrono::steady_clock::now().time_since_epoch().count();
        return f(x + s);
    }
};
HT<i64, int, H> mp;
```
#### 注意事项
- 默认 `resize()` 并不能像 `unordered_map::reserve()` 一样直接调用
- 不要默认存在 `count()`
- 需要防构造数据时仍建议自定义哈希
#### 复杂度
- 查询、插入、删除：期望 $O(1)$
- 最坏仍可能退化
### Pairing Heap
---
PBDS 堆最实用的用途是保存节点句柄，从而直接修改或删除堆内任意元素
```cpp
template<class T, class C = less<T>>
using PH = __gnu_pbds::priority_queue<T, C, pairing_heap_tag>;
```
#### 接口
普通堆之外主要使用
- `q.push(x)`：插入并返回节点句柄
- `q.modify(it, x)`：修改指定节点
- `q.erase(it)`：删除指定节点
- `q.join(b)`：合并 `b`，之后 `b` 为空
#### 常见用法
可修改小根堆
```cpp
using E = pair<i64, int>;
PH<E, greater<E>> q;
auto it = q.push({10, u});
q.modify(it, {5, u});
q.erase(it);
```
保存句柄
```cpp
using Q = PH<pair<i64, int>, greater<pair<i64, int>>>;
Q q;
vector<Q::point_iterator> p(n);
p[u] = q.push({d[u], u});
q.modify(p[u], {nd, u});
```
合并两个堆
```cpp
a.join(b);
```
#### 注意事项
- 节点被 `erase()` 或 `pop()` 后，对应句柄失效
- 保存句柄时要额外维护节点当前是否仍在堆中
- Dijkstra 通常用重复入堆更简单，只有确实需要 decrease-key 时再使用 `modify`
#### 复杂度
- `push`：$O(1)$
- `modify`、`erase`、`pop`：均摊 $O(\log n)$
- `join`：$O(1)$
### 结构选择
| 需求 | 优先选择 |
|---|---|
| 动态排名、第 $k$ 小 | `RBT` |
| 按键 Splay、自调整访问 | `SPT` |
| 查询很多、修改极少 | `OVT` |
| 字符串前缀范围 | `PT` |
| 高性能哈希表 | `HT` |
| 可修改、可删除、可合并堆 | `PH` |
