### 数据结构与区间维护

#### BIT 倍增替代二分套树状数组

##### 适用场景

如果需要在树状数组上反复二分某个前缀位置，例如找第一个前缀和达到阈值的位置，直接二分套 BIT 查询是 $O(\log^2 n)$，可以用 BIT 倍增优化到 $O(\log n)$。

##### 核心思路

树状数组节点 $x$ 维护的是区间：

$$
[x-\operatorname{lowbit}(x)+1,x].
$$

查找位置时，从最高二进制位到最低二进制位尝试扩展答案。维护当前已经确定的位置 $pos$ 和前缀值 $sum$。

若加入 $pos+2^k$ 对应的 BIT 块后仍满足条件，就令：

$$
pos\leftarrow pos+2^k,
$$

并同步更新 $sum$。

这样可以避免二分过程中重复查询前缀和。

##### 模板形式

```cpp
int pos = 0;
long long cur = 0;
for (int k = LOG; k >= 0; --k) {
    int nxt = pos + (1 << k);
    if (nxt <= n && cur + bit[nxt] < target) {
        pos = nxt;
        cur += bit[nxt];
    }
}
// pos + 1 是第一个前缀和 >= target 的位置
```

##### 易错点

- 判断条件要根据“找第一个 >= target”还是“找最后一个 < target”调整。
- BIT 下标必须从 $1$ 开始更方便。
- 数组元素必须非负，使前缀和单调；仅有可加性不够。要求 target > 0；超过总和时返回 n+1。LOG 取 floor(log2(n))（n=0 时可取 0），使用 i64 保存前缀和且不允许溢出。

#### BIT 可线性重构

##### 适用场景

已知原数组，需要初始化树状数组时，不必逐点 add。

##### 核心思路

先令 $tree_i=a_i$，再对每个 $i$，把 $tree_i$ 加到 $tree_{i+lowbit(i)}$。这样每个位置只向父节点贡献一次，整体 $O(n)$ 建树。

##### 使用条件

- 转化前后的信息必须等价，不能丢失题目真正需要维护的量。
- 通常适用于该结构能够被预处理、离线排序、分组维护或用数据结构快速合并的场景。

##### 易错点

这是构建静态初始 BIT 的技巧，不改变后续单点修改和前缀查询写法。

##### 校验补充
必须按 i 从小到大传播，且只在 i+lowbit(i)<=n 时更新父节点。

#### Trie 上交换子树实现值域操作

##### 适用场景

当维护一个数值集合，并支持按位异或、按位或、按位与等值域操作时，可以把数放在 Trie 或动态开点值域线段树上，通过交换或合并子树实现操作。

##### 核心思路

在二进制 Trie 中，每一层对应一个二进制位，每个节点的左右儿子分别表示当前位为 $0/1$。

- 整体异或某一位为 $1$：交换这一层对应节点的左右儿子。
- 按位或某一位为 $1$：所有该位为 $0$ 的数会变成 $1$，相当于把左子树合并到右子树。
- 按位与可以用或和异或转化，或直接对不合法子树进行合并/清空。

##### 常见用途

- 维护集合中不同数个数；
- 对值域区间进行位运算；
- 三进制或其他进制 Trie 中的儿子轮换、交换。

##### 易错点

- Trie 建树方向要和操作匹配，有的进位操作需要从低位向高位建。
- 合并子树时要维护计数和答案信息。
- 区间操作通常需要配合 split / merge 或动态开点线段树。

#### 万能 hash

支持 array、vector、pair、tuple 及其嵌套。使用 `unordered_set<Key, UniversalHash>` 或 `unordered_map<Key, Value, UniversalHash>`。不要为全由标准库类型组成的键向 std 添加 hash 偏特化。哈希可能碰撞，容器仍用相等比较区分键。
```cpp
struct UniversalHash {
    template<class T> static size_t get(const T& x) { return std::hash<T>{}(x); }
    template<class T> static void add(size_t& h, const T& x) {
        h ^= get(x) + size_t(0x9e3779b9) + (h << 6) + (h >> 2);
    }
    template<class A, class B> static size_t get(const pair<A,B>& x) {
        size_t h=0; add(h,x.first); add(h,x.second); return h;
    }
    template<class... T> static size_t get(const tuple<T...>& x) {
        size_t h=0; apply([&](const auto&... y){(add(h,y),...);},x); return h;
    }
    template<class T, size_t N> static size_t get(const array<T,N>& x) {
        size_t h=0; for(const auto& y:x) add(h,y); return h;
    }
    template<class T> static size_t get(const vector<T>& x) {
        size_t h=0; for(const auto& y:x) add(h,y); return h;
    }
    template<class T> size_t operator()(const T& x) const {return get(x);}
};
```

#### 主席树视作静态树套树

##### 适用场景

当一个问题用树套树能做，但没有修改或修改只体现在前缀版本时，可以考虑用主席树降复杂度。

##### 核心思路

主席树的每个版本表示一个前缀或历史状态，相邻版本只差一次插入。区间信息可由两个版本相减得到，相当于把外层位置维静态化，内层权值维用可持久化线段树维护。

##### 使用条件

- 转化前后的信息必须等价，不能丢失题目真正需要维护的量。
- 通常适用于该结构能够被预处理、离线排序、分组维护或用数据结构快速合并的场景。

##### 易错点

主席树适合静态前缀差分，不适合任意在线修改。值域需要离散化或动态开点。

#### 倍增优化区间并查集合并

##### 适用场景

当题目要求多次把两个等长区间逐位合并，例如要求 $[l_1,r_1]$ 和 $[l_2,r_2]$ 对应位置相等时，直接逐点合并会退化为 $O(nm)$。这时可以用倍增思想优化。

##### 核心思路

类似 ST 表，将长度为 $2^k$ 的区间作为一个整体节点。

令 $fa[k][i]$ 表示区间 $[i,i+2^k-1]$ 所属的并查集代表元。若要合并两个等长区间 $[l_1,r_1]$ 和 $[l_2,r_2]$，令 $k=\lfloor\log_2(r_1-l_1+1)\rfloor$，只需合并：

$$
[l_1,l_1+2^k-1]\leftrightarrow [l_2,l_2+2^k-1],
$$

以及

$$
[r_1-2^k+1,r_1]\leftrightarrow [r_2-2^k+1,r_2].
$$

最后再从大长度向小长度下传合并关系，把 $2^k$ 的区间拆成两个 $2^{k-1}$ 的区间。

##### 复杂度

预处理和下传共 $O(n\log n\alpha(n))$，每次区间约束只需要 $O(\alpha(n))$ 次合并。

##### 易错点

- 倍增区间的合并只是记录约束，最终必须从高层向低层拆分传播。
- 区间长度不是 $2^k$ 时，要用左右两个 $2^k$ 区间覆盖。
- 只适合“对应位置相等/合并”这类满足可拆分性的约束。

#### 分块 ST 表降低 RMQ 空间

##### 适用场景

普通 ST 表可以 $O(1)$ 回答静态区间最值，但空间为 $O(n\log n)$。当 $n$ 很大或空间受限时，可以分块后只对块建立 ST 表。

##### 核心思路

设块长为 $B$。预处理：

1. 每个位置到所在块左端的前缀最值；
2. 每个位置到所在块右端的后缀最值；
3. 每个整块的最值，并对块序列建立 ST 表。

查询 $[l,r]$ 时：

- 若 $l,r$ 在同一块，直接块内处理；
- 否则答案由三部分取最值：
  - $l$ 到其所在块右端的后缀最值；
  - 中间完整块的 ST 表答案；
  - $r$ 所在块左端到 $r$ 的前缀最值。

##### 复杂度

空间约为：

$$
O\left(n+\frac nB\log\frac nB\right).
$$

取合适块长后可明显小于普通 ST 表。

##### 易错点

- 同块查询需要单独处理。
- 块间 ST 表维护的是“整块最值”，不是原数组位置。
- 块长选择要结合时间和空间限制。

#### 删除困难时维护前后缀结构

##### 适用场景

如果某种结构支持加入但不支持删除，例如线性基删除、非质数模除法、某些哈希逆操作，可以考虑前后缀分解。

##### 核心思路

对静态序列预处理前缀结构 $pre_i$ 和后缀结构 $suf_i$。删除区间或单点时，用删除部分左右两侧的信息合并得到答案。

##### 使用条件

- 转化前后的信息必须等价，不能丢失题目真正需要维护的量。
- 通常适用于该结构能够被预处理、离线排序、分组维护或用数据结构快速合并的场景。

##### 易错点

结构的合并操作要可行。若删除位置在线修改变化频繁，纯前后缀预处理不够。

#### 区间加组合数用高阶差分

##### 适用场景

当区间更新不是常数，而是关于位置的多项式或组合数形式时，可以用高阶差分。

##### 核心思路

组合数满足 $\binom{x}{k}$ 的差分仍是组合数。把要加的函数展开到组合数基底上，对每一阶差分数组做常数区间加，最后多次前缀和还原。

##### 使用条件

- 转化前后的信息必须等价，不能丢失题目真正需要维护的量。
- 通常适用于该结构能够被预处理、离线排序、分组维护或用数据结构快速合并的场景。

##### 易错点

组合数基底下边界项容易错，建议用小数据手算验证。

#### 单侧递归线段树处理区间可见性

##### 适用场景

当线段树区间信息无法简单由左右儿子直接合并，但查询时一侧一定完整保留，另一侧需要根据阈值递归判断时，可以使用单侧递归线段树。

##### 核心思路

以“从原点能看到多少楼房”为例。每个位置 $i$ 的可见性由斜率决定。线段树节点维护：

- $mx$：该区间最大斜率；
- $cnt$：在没有额外遮挡时，该区间内可见的数量。

查询右子区间时，需要知道左侧已经形成的最大斜率阈值 $x$。递归函数 $solve(o,x)$ 表示在阈值为 $x$ 的情况下，节点 $o$ 的区间贡献多少。

若左儿子的最大斜率 $\le x$，左儿子完全无贡献，直接递归右儿子；否则先递归左儿子，再把右儿子中超过左侧最大斜率的部分加入。

##### 复杂度

修改一个点后更新路径。由于每层可能触发一次递归，常见复杂度为：

$$
O(\log^2 n)
$$

每次操作。

##### 易错点

- 合并信息不是普通的 $cnt_L+cnt_R$，右区间贡献依赖左区间最大值。
- 比较斜率时尽量用交叉乘避免精度误差。
- 单侧递归依赖“左侧一定优先影响右侧”这类方向性。

#### 复杂区间修改用矩阵维护

##### 适用场景

当一次修改会同时改变多个统计量，且这些统计量之间是线性关系时，可以用矩阵表示修改。

##### 核心思路

把节点维护的信息写成向量 $v$，一次操作写成矩阵 $M$，更新就是 $v\leftarrow Mv$。多个操作复合对应矩阵乘法，因此可作为线段树懒标记。

##### 使用条件

- 转化前后的信息必须等价，不能丢失题目真正需要维护的量。
- 通常适用于该结构能够被预处理、离线排序、分组维护或用数据结构快速合并的场景。

##### 易错点

矩阵乘法通常不交换，懒标记下传时要保持操作顺序。

#### 将直方图横向分解为笛卡尔树

##### 适用场景

当题目在一个柱状图、直方图或高度数组上进行计数、放置、覆盖等操作时，可以考虑把直方图按高度横向切分，并建立笛卡尔树。

##### 核心思路

对于高度序列 $h_1,h_2,\ldots,h_n$，以最小高度为根建立笛卡尔树。根对应整段中最底部的一层矩形，左右儿子对应被最小值分开的左右子直方图。

这样，原本二维的直方图可以转化为一棵树：

- 每个节点对应一个极大横向矩形；
- 子树对应该矩形上方的若干独立区域；
- 很多放置/计数问题可以在树上做 DP。

##### 常见 DP 形式

设 $f_{u,k}$ 表示节点 $u$ 的子树内放置 $k$ 个对象的方案数。转移时先合并左右儿子，再考虑当前节点对应矩形中新增的行或列贡献。

##### 易错点

- 笛卡尔树通常按最小高度建，表示从下往上切分。
- 当前节点对应的矩形高度应减去父节点高度。
- 如果有相同高度，需要固定稳定的比较规则，避免树结构不唯一导致实现混乱。

#### 并查集维护集合和支持单点改权

##### 适用场景

如果集合只合并不拆分，同时要查询每个连通块权值和，可以在并查集根上维护和。

##### 核心思路

每个根维护当前集合的权值和。合并两个集合时把和加到新根上。单点权值改变时，找到该点当前所在根，将根的和加上权值变化量。

##### 使用条件

- 转化前后的信息必须等价，不能丢失题目真正需要维护的量。
- 通常适用于该结构能够被预处理、离线排序、分组维护或用数据结构快速合并的场景。

##### 易错点

如果需要移动单个元素到另一个集合，普通并查集不够，需要额外编号或可删除并查集技巧。

#### 摩尔投票维护区间高频候选

##### 适用场景

当需要找区间内出现次数超过一定比例的元素时，可以用摩尔投票合并候选。

##### 核心思路

摩尔投票能在线性扫描中保留可能超过半数的候选。推广到前 $k$ 高频候选时，可以维护有限个候选及抵消次数，并在线段树节点间合并。最后对候选真实出现次数进行验证。

##### 使用条件

- 转化前后的信息必须等价，不能丢失题目真正需要维护的量。
- 通常适用于该结构能够被预处理、离线排序、分组维护或用数据结构快速合并的场景。

##### 易错点

摩尔投票只保证候选集合包含答案，不保证候选一定合法，必须二次计数。

##### 校验补充
保留 k 个 Misra–Gries 候选保证包含频率严格超过 1/(k+1) 的元素，不保证包含真正频数排名前 k 的所有元素。

#### 数组区间加等差数列

对一个数组 $a$ 进行 $q \left ( q\leqslant 10^{5} \right )$ 次区间 $\left [ l,r \right ]$ 加以 $x$ 为首项，$d$ 为公差的等差数列，相当于对于 $i\in \left [ l,r \right ]$ 加 $x+\left ( i-l \right )d$, 即 $id+x-ld$ 。因此可以额外维护俩个差分数组  $b$ 和 $c$ , 数组  $b$ 区间加  $d$ , 数组  $c$  区间加 $\left ( x-ld \right )$ 。求前缀和后新数组的 $a_{i}^{'}$ 为 $a_{i}^{'}=a_{i}+ib_{i}+c_{i}$ 。

#### 数颜色转为统计前驱位置

##### 适用场景

静态区间询问不同颜色个数时，可以把颜色是否首次出现转为前驱位置限制。

##### 核心思路

令 $pre_i$ 为位置 $i$ 前一个相同颜色的位置。区间 $[l,r]$ 内颜色数等于满足 $i\in[l,r]$ 且 $pre_i<l$ 的位置数。这就变成二维数点，可用离线树状数组、主席树或莫队处理。

##### 使用条件

- 转化前后的信息必须等价，不能丢失题目真正需要维护的量。
- 通常适用于该结构能够被预处理、离线排序、分组维护或用数据结构快速合并的场景。

##### 易错点

这里统计的是每种颜色在区间内第一次出现的位置。带修改时需要更复杂的数据结构。

#### 最值比较问题放到笛卡尔树上

##### 适用场景

当区间答案由最大值或最小值支配，并且需要比较大小或分治统计时，可以考虑笛卡尔树。

##### 核心思路

笛卡尔树把区间最值变成树上 LCA 或祖先关系。以区间最值为分治点的递归结构，可以直接对应笛卡尔树的子树结构，从而优化枚举区间。

##### 使用条件

- 转化前后的信息必须等价，不能丢失题目真正需要维护的量。
- 通常适用于该结构能够被预处理、离线排序、分组维护或用数据结构快速合并的场景。

##### 易错点

最大笛卡尔树和最小笛卡尔树方向不同。同值时要固定稳定规则，否则结构不唯一。

#### 绝对众数可用摩尔投票信息维护

##### 适用场景

当题目涉及绝对众数，即出现次数严格大于区间长度一半的元素时，可以考虑使用摩尔投票信息维护候选值。

##### 核心性质

1. 一个序列至多有一个绝对众数。
2. 摩尔投票信息可以用二元组 $(val,cnt)$ 表示，并且可以合并。
3. 若一个区间存在绝对众数，则摩尔投票得到的候选值一定是它。

合并两个信息 $(x,a)$ 和 $(y,b)$：

$$
(x,a)+(y,b)=
\begin{cases}
(x,a+b),&x=y,\\
(x,a-b),&x\ne y, a>b,\\
(y,b-a),&x\ne y, b>a,\\
(0,0),&x\ne y, a=b.
\end{cases}
$$

##### 使用方式

数据结构中维护摩尔投票二元组，查询区间时先得到候选值，再额外统计候选值真实出现次数，判断是否超过区间长度一半。

##### 易错点

- 摩尔投票只能给候选值，不能直接证明它一定是众数。
- 最后必须再查一次出现次数验证。
- 合并顺序不影响结果的候选正确性，适合线段树、平衡树等维护。

#### 静态区间单调栈用倍增处理

##### 适用场景

静态数组中，如果每次查询要模拟单调栈弹栈过程，可以预处理倍增跳跃。

##### 核心思路

先求每个位置在单调栈意义下的下一个支配位置，形成一棵树或一条跳链。区间查询时用倍增从起点向后跳，直到越过右端点。

##### 使用条件

- 转化前后的信息必须等价，不能丢失题目真正需要维护的量。
- 通常适用于该结构能够被预处理、离线排序、分组维护或用数据结构快速合并的场景。

##### 易错点

该技巧依赖数组静态。带修改时 next 关系会变化，不能直接倍增。
