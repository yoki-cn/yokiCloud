### 选择、区间合并与小并大
---
#### 第 k 小选择
---
只需要第 `k` 小而不需要完整排序时使用 `nth_element`
C++20：
```cpp
ranges::nth_element(a, a.begin() + k);
auto x = a[k]; // 0base 第 k 小
```
传统写法：
```cpp
nth_element(a.begin(), a.begin() + k, a.end());
auto x = a[k];
```
##### 接口说明
- `nth_element(first,nth,last)`：重排 `[first,last)`，使 `*nth` 等于完整排序后该位置的元素
- `k` 为 `0base`，要求 `0 <= k < a.size()`
##### 注意事项
执行后只保证：
- `a[k]` 为第 `k` 小
- `[0,k)` 中没有元素大于 `a[k]`
- `(k,n)` 中没有元素小于 `a[k]`
- 左右两部分内部均不保证有序
若需要前 `k` 小且内部有序，可以先 `nth_element` 再只排序前半部分：
```cpp
ranges::nth_element(a, a.begin() + k);
ranges::sort(a.begin(), a.begin() + k);
```
##### 复杂度
平均时间复杂度 $O(n)$，额外空间由实现决定
#### 区间合并
---
默认处理左闭右开区间 `[l,r)`，忽略空区间，相交或首尾相接的区间都会合并
```cpp
template<class T>
vector<pair<T, T>> merge_seg(vector<pair<T, T>> a) {
    ranges::sort(a);
    vector<pair<T, T>> res;
    for (auto [l, r] : a) if (l < r) {
        if (res.empty() || res.back().second < l) res.push_back({l, r});
        else res.back().second = max(res.back().second, r);
    }
    return res;
}
```
##### 接口说明
- `merge_seg(a)`：合并所有相交或首尾相接的区间
- 返回结果按左端点递增，且两两严格分离
##### 注意事项
当前判断：
```cpp
res.back().second < l
```
因此 `[1,3)` 与 `[3,5)` 会合并

若首尾相接也要视为分离，改为：
```cpp
res.back().second <= l
```
若题目使用闭区间 `[l,r]`，需按题意重新判断“相邻”是否也应合并，不建议把不同区间语义混进同一个接口
##### 复杂度
排序 $O(n\log n)$，扫描 $O(n)$，额外空间 $O(n)$
#### 小并大
---
核心规则：**始终把较小容器中的元素搬到较大容器**
`map` / `unordered_map` 统计：
```cpp
if (a.size() < b.size()) swap(a, b);
for (auto [x, v] : b) a[x] += v;
b.clear();
```
集合：
```cpp
if (a.size() < b.size()) swap(a, b);
for (auto x : b) a.insert(x);
b.clear();
```
##### 原理
若一个元素每次都从较小集合搬入较大集合，则搬运后它所在集合的大小至少翻倍
因此一个元素最多被搬运
$$
O(\log n)
$$
次
##### 注意事项
- 小并大的关键不是容器类型，而是**每次必须小集合并入大集合**
- 合并后通常不再需要原来的小集合，因此可以直接 `clear()`
- 如果后续仍需分别保留两个集合，就不能直接套用这种复杂度分析
- 实际题目中的合并逻辑通常不同，因此不建议封装成统一的 `small_to_large()` 回调函数
- 若使用 `unordered_map`，复杂度依赖哈希性能；担心被卡时使用安全哈希
##### 常见用法
树上 DFS 中每个节点维护一个颜色计数表：
```cpp
void dfs(int u, int fa) {
    for (int v : g[u]) if (v != fa) {
        dfs(v, u);
        if (cnt[u].size() < cnt[v].size()) swap(cnt[u], cnt[v]);
        for (auto [c, x] : cnt[v]) cnt[u][c] += x;
        cnt[v].clear();
    }
    ++ cnt[u][col[u]];
}
```
这里 `cnt[u]` 始终保存当前子树合并后的结果
##### 复杂度
若共有 $n$ 个初始元素：
- 单次插入均摊 $O(1)$ 的哈希容器：通常 $O(n\log n)$
- `map` / `set` 单次插入 $O(\log n)$：通常 $O(n\log^2 n)$
- 还需额外计入每道题自身的统计、删除或答案维护代价
